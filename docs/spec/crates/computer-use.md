# pawork-computer-use

> 独立 computer use 库，2026-09-17 按用户授权新增，并按“不干扰本机键鼠”的要求改为隔离桌面。CU-17 起 pawork-app 直接依赖本包承载 GUI 目标注册表（生产入口 `NativeHost::host()` → `HostSurface::local()`）；隔离桌面动作仍经 tools → Host。本包不改 GUI wire 或 domain 事件。

## 1. 职责与边界

CU-21 增加显式隔离应用表面：容器内 Rust `computer_guest` 经 X11 / D-Bus / AT-SPI 识别 Firefox，Host 的 `GuestSurface` 复用现有 NativeHost / TargetRegistry / 审批与句柄，图像仍由同一 RFB 连接裁剪。身份为 `guest.browser.firefox`、应用族 Browser，不把 GTK 标为 AppKit。默认本机 Host 不改变；部署见 [README](../../../crates/computer-use/README.md)。

CU-26 切片 1 新增 Linux-only 的 `wayland` 模块：guest 侧专用 Sway / wlroots seat 客户端。它是纯 Rust 的 Wayland wire 实现，只绑定 CU-23 证实的 `zwlr_screencopy_manager_v1`（整输出截图）、`zwlr_virtual_pointer_manager_v1`（点击）和 `zwp_virtual_keyboard_manager_v1`（按键 / 文本），另用 Sway IPC 取 compositor 权威的窗口身份（pid 来自客户端凭证、con id、代际）并校验 seat 专用。CU-26 切片 2 把它接到 guest 帧协议：`computer_guest --wayland` 在容器内 `0.0.0.0:5907` 提供 `capture` / `input`，Host 侧的 `WaylandSurface`（`NativeHost::wayland()`，全平台编译）复用 NativeHost 的审批、占用、单次凭证、取消与动作后新观测，点击 / 按键按截图租约派发（`NativeRequest::ObservedClick` / `ObservedKeys`）。CU-26 切片 3 把它接入正式链路：`pawork-tools` 的 `NativeComputerTool::wayland` 暴露 `observed_click` / `observed_keys`，App 在显式 `--computer-native wayland` 时选用 `shared_wayland_host()`。默认入口不变（`host`）。真实证据都来自本机独立 user + netns：一是经 `wayland_host_probe` 的 Host 链路 smoke（截图、点击、文本、Return、过期租约与撤销拒绝）；二是 app 的 `cu26_live`，按 `gui serve` 同款装配经 GUI 协议审批与目标批准驱动 `computer_native`，有持久观测（脚本 Provider）。三是 2026-10-14 以 `pawork --computer-native wayland gui serve` 二进制为 Host、GPUI Desktop 真窗口审批与目标批准、真实 Provider `glm-coding / glm-5.3-flash` 驱动的整条链路（discover → request → bind → screenshot → 点击 → 文本 → Return），外部事实为目标终端收到的点击字节与文本。当时还没有专用容器内的验收。2026-10-14 修了 `WaylandSurface::resolve` 把 guest 元数据或连接错误折叠成「未安装」：guest 帧服务的读预算是 20 秒，空闲更久后服务端关掉 Host 缓存的连接，下一次 `metadata` 失败曾被收成 None。现在这条死连接重拨一次；重拨或元数据仍失败时按 `ProbeUnavailable` 上报，元数据成功但 bundle 不在列表里才是「未安装」，目标未批准仍是 `NotAuthorized`。失败 Run 第二次 `bind`（空闲约 72 秒）与 attempt 2 的 `request`（空闲约 23 秒）是这次误报的会话证据；成功 Run 的调用间隔都短于 20 秒。Desktop 尾窗漏掉更早观测时的有界回填见计划「面板列出 0 条观测」（离线回归，未重开真窗口）。2026-10-15 同一类 netns 里，`wayland_host_probe --boundaries` 在真实 Sway 上记录了撤销后的 NotAuthorized、派发前取消的 Cancelled、断线后的 ProcessRestarted / WindowReplaced 与重新 bind，以及第二 scope 的 TargetOccupied 和 `close_scope` 之后的让出。Wayland 表面没有独立接管入口（`activity` 恒为 Idle）。同日 `wayland_host_probe --partial-receipt` 在同类 netns 里，于前缀已经进入 seat 之后记录了 `partial 1/11`（`events.bin` 只有 `I`，不自动补完）和 `unknown_effect`（只有 `L`，派发事实保留）。点击序列中途的 Partial 没有打到。2026-10-15 在 rootless podman 容器里补了最小验收：只读根、能力集为 0、network none、无端口发布，容器外的 `wayland_host_probe` 经 Unix socket 完成截图、点击与文本。唯一宿主挂载是该 socket 目录，宿主 5907 的 x11vnc 未改。这还不是 CU-23 的无 bind 全文，也没有在该容器里重跑 GUI 审批或真实 Provider。见 [CU-26](../../plan/cu-26-wayland-production.md)。

纯 Rust 通过 RFB 3.8 操作专用容器内的 Xvnc 虚拟桌面。所有截图和输入都在独立显示器，不接触本机 HID、屏幕、焦点或剪贴板；不存在 macOS 回退实现。应用须运行于该环境，不能直接控制宿主已有应用。无 Pawork 内部依赖、GPUI、Provider、shell、自有 JS Runtime 或模型指定的路径/网络端点。容器需显式启动，库不管理 Docker 进程。

CU-02 起新增 `target` 模块：本机后台目标、观测与动作能力的有类型契约（纯数据类型与校验逻辑，不触平台 API、不触网）。本机探针与动作派发由 CU-03+ 落地，CU-10 native 接线见下文；GUI 不直接访问。

CU-16 起新增 `approval` 模块：应用与网站范围的 Host 审批契约。授权把 `TargetIdentity`（整应用或浏览器内单源网站）绑定 workspace/run `Scope`，由宿主在显式用户审批后签发 once / for-run 授权；`TargetRegistry` 在绑定、观测、校验与派发路径上先查台账授权，未授权、已撤销、跨目标与受保护目标先于任何 probe 调用拒绝；网站目标另经 `NativeProbe::current_origin` 接缝复核窗口当前页面身份（含宿主捕获前预检 `require_authorized`），同窗口跨源导航即拒。Pawork 自身 UI 与 OS 权限界面内置为受保护目标。OS 权限（Screen Recording / Accessibility / Automation）与 Pawork 目标授权分离：契约不授予、不变更系统权限，缺失由 CU-03+ 探针如实报告。


CU-03 起新增 `macos` 模块（仅 macOS）：`NativeProbe` 的真实后端与应用发现、窗口选择与受控启动。发现只读窗口服务器元数据（bundle id + 族、进程实例、窗口计数），不读标题、不读 AX 树；标题与 AX 读取是目标内容访问，`list_windows` 先核验目标与 scope 授权再读，标题只在该调用显式要求时复制出窗口服务器。窗口存活用应用自身 AXWindows 交叉验证（已关闭窗口在窗口服务器列表长期残留为幽灵）：私有但长期稳定的 `_AXUIElementGetWindow` 可用时按窗口服务器 id 精确对应（幽灵 id 永不映射，同帧关窗只失效自己），符号缺失时退化为帧组闭合（同帧窗口服务器计数 = AX 计数才判活，歧义 fail-closed 且可能连带失效同帧幸存窗）。启动只接受 LaunchServices 可解析的 bundle 身份（模型不能传可执行路径），授权检查先于一切系统调用，启动不激活、不夺焦点。Accessibility 缺失按 `PermissionMissing`、其余 AX 失败按 `ProbeUnavailable` 如实拒绝；网页 origin 仍无信号源、按契约 fail-closed（AX 树版本信号源由 CU-05 落地）。生产 native 接线见下文 CU-10 记录；真实验收与各 CU 既有探针结果分开。

CU-04 起 `macos` 模块新增窗口级截图：`capture_window` 按 CU-01 实测的 ScreenCaptureKit 单帧窗口捕获路线实现（桌面无关过滤器，遮挡 / 后台 / 最小化窗口仍返回自身内容，不激活目标、不动前台与焦点）。门槛顺序：台账授权 → 进程实例 → 身份绑定（实例 pid 的 bundle id 系统回读须等于获授权身份，与 `list_windows` 共用同一核验，错配按 Invalid 先于任何 AX 读取拒绝）→ 窗口存活 + 代际（复用 CU-03 同一快照证明）→ OS Screen Recording preflight（权限拒绝先于捕获缝，永不发起 TCC 请求）；SCWindow 按窗口 id + 属主 pid 双因子定位，输出经 `scalesToFit` 铺满配置帧（内容恒覆盖全图，整图坐标换算才成立），捕获与存活证明之间关窗按 WindowReplaced、其余捕获失败保留 OS 原因按 ProbeUnavailable 如实拒绝，无旧图 / 残帧路径。上限沿用现有口径：原始像素单边 ≤4096、总像素 ≤8M、捕获比例 ≤2x，输出基线 JPEG 最长边 ≤1280、字节 ≤512KiB（质量阶梯 75/50/30），completion handler 10 秒超时；产物继续走现有 ContentPart::Image 与持久消息通路。契约层相应新增 `NativeProbe::window_size` 接缝：观测记录窗口尺寸，缩放后旧观测在注册 / 消费 / 元素派发三路按 StaleHandle 拒绝（恢复尺寸后在途租约可放行），尺寸不可得按 WindowReplaced fail-closed。生产 native 接线见下文 CU-10 记录；真实验收与各 CU 既有探针结果分开。

CU-05 起新增有界无障碍树与元素定位。契约层（src/target/ax_tree.rs）提供 `AxTreeBounds`（深度 24 / 节点 4096 / 单串 200 字符 / 整读 10 秒，固定常量不可按调用调）、`AxTreeRead`（前序节点流，nodes[0] 恒为窗口根）、`ax_tree_revision` 版本指纹（窗口本地坐标，纯移动不推进版本）、`ElementQuery` / `ElementLookup` / `lookup_element`（角色 + 名称查找，歧义不取第一，截断树下唯一匹配不可证不签发）。macOS 后端落地 `MacosNative::read_ax_tree` 与真实 `tree_revision`：门序为台账授权 → 进程实例 → 身份绑定 → Accessibility preflight → 窗口存活 + 代际 → 有界遍历；读使能对 Chromium 族先设 `AXManualAccessibility`（VoiceOver 同款，幂等不改 UI，渲染进程异步物化树、首读可能如实只含窗口铬）。时间预算同一 deadline 贯穿窗口解析 / 读使能 / 遍历，每次 AX 调用以该次调用开始时的剩余预算为逐元素 messaging timeout、返回后复核时钟、交付前最终复核，符号缺失或设置失败拒读。敏感边界：永不读 AXValue；安全输入框按 subrole 识别（AXTextField + AXSecureTextField，识别失败保守按敏感）连名都不读；名称读取失败置 names 标志使名称查询不可证（角色单条件查询不受影响）；子列表与上报计数不一致直接拒读。读失败是错误，成功读的根无子是「应用未暴露元素」的肯定答案，空树不伪装。生产 native 接线见下文 CU-10 记录；真实验收与各 CU 既有探针结果分开。

CU-09 起所有权与接管落地。隔离桌面路径（lib.rs）把进程级全局串行锁改为绑定到实际共享边界的 run 所有权：`Computer::isolated()` 的全部实例共享一个桌面会话槽（一个部署只有一个桌面），首个 Run 认领后其它 Run 的任何动作（含 status）按 `Error::Conflict` 明确拒绝且零后端访问；取消 / 超时即时释放占用并作废待用观测（backend 仍平衡键鼠按下），空闲超过 `OWNERSHIP_TTL`（60 秒，与观测租约同寿）自动失去拥有权，宿主在 Run 结束时显式 `Computer::release(scope)`（释放作废待用观测并推进 generation，在途操作只验证原所有权、不得重新认领空槽——在途截图存租约前复核原代际（同 scope 重认领后按 Stale 拒绝），在途输入的 backend 取消谓词并入所有权撤销与操作代际（release 后剩余事件停止发送）；认领后的 backend 调用失败叠加取消同样释放占用）。契约层（src/target/registry.rs）新增目标占用与用户接管：应用（或网站目标所在的浏览器进程）为物理争用边界，`TargetRegistry` 按 anchor 记录占用 Run，bind 在存活与 origin 校验通过后才认领（失败绑定不留占用），观测 / 校验 / 派发 / 宿主预检 `require_authorized` 全链拒绝第二个 Run（`TargetOccupied`）；`pause_dispatch` / `resume_dispatch` 承接宿主的用户接管信号，暂停期间派发闸按 `UserActive` 让出且不消耗任何租约（观测保持可用，接管结束后重观测）；`release_scope` 在 Run 终止时作废该 scope 全部句柄并释放占用，`revoke` / `revoke_scope` 保留 CU-16 的 NotAuthorized 阻断语义并额外释放占用。生产 native 接线见下文 CU-10 记录；真实验收与各 CU 既有探针结果分开。

CU-06 起落地后台 AX 语义动作。契约层新增 `SemanticAction`（Press / SetValue / InsertText——仅 CU-01 实测无干扰的动作；CU-01 未实测到独立 select 动作故不暴露，`InsertText` 即实测的「选择」原语：替换当前选区，塌缩选区即插入）与 `SemanticOutcome`（`Dispatched`：AX 调用返回成功，是派发而非效果证明，须以新观测或目标侧事实复核；`UnknownEffect`：messaging 超时，动作可能已生效，不盲目重试），文本载荷按字符计上限 4096（`MAX_SEMANTIC_TEXT_CHARS`，空串合法即清空），每个动作映射既有 `NativeActionKind`（AxPress / AxSemanticWrite）并过同一 `require_background` 能力闸——Unverified 与 Unsupported 同拒，不存在全局或前台输入回退。macOS 后端新增 `MacosNative::semantic_action`：取消谓词 → 派发侧台账授权（`consume_dispatch_permit`：消费元素句柄时铸单次派发凭证 `DispatchPermit` 随 `ValidatedElement` 携带，首次派发尝试标记 armed、再次消费拒绝，NativeHost 在平台调用返回后退役 ticket；原台账的撤销 / 重授推进代次并作废在途票据，克隆消费结果无法二次派发）→ 载荷校验 → 进程实例 → 身份绑定 → 能力闸（先于一切 AX 接触，Chromium 语义写在此零接触拒绝）→ Accessibility preflight → 存活 + 代际 → 同边界重走复核树版本（不一致按 TreeChanged）→ 子索引路径重解析 → 写类动作复核 role/subrole（安全输入框按 Invalid 拒，与读侧永不读安全内容对称）→ 取消复查 → armed 单次 AX 调用（不可回退点，返回码单独定终态）；同一 deadline（AX_TREE_BOUNDS.max_read）贯穿存活证明、窗口解析、版本复核、路径解析与动作调用，存活读取超时保留超时原因而非伪装 WindowReplaced。元素自身肯定拒绝（ActionUnsupported / AttributeUnsupported）按新变体 `TargetError::ElementUnsupported` 如实上报。生产 native 接线见下文 CU-10 记录；真实验收与各 CU 既有探针结果分开。

CU-07 起落地后台定向文本与按键输入（CU-06 语义写之外、CU-01 实测支持后台的另一路线）。契约层新增 `TargetedKey`（14 个非打印键；可打印字符只能走 `InsertText` 文本——Unicode 键事件是实测的后台路线，字符 keycode 依赖目标键盘布局、契约不可见）、`KeyModifiers`（shift / control / option；Command 刻意不可表示——命令组合即菜单快捷键，CU-01 实测后台不路由，语义路线或前台流程替代，无后台回退）、`TargetedKeyPress`、`TargetedInput`（InsertText：在目标元素当前插入点输入、替换非空选区，从不整值替换——那是 CU-06 SetValue；KeyPress：带修饰组合的一次按键）、`TargetedOutcome`（`Dispatched`：全部计划事件已投递到目标 pid，CGEventPostToPid 无回执，只是派发证明非效果证明；`Partial`：序列中途停止（取消、目标失活或绑定复核失败），按下状态已释放、已投事件可能已生效，绝不当作干净失败静默重试）与 `TargetError` 第十九变体 `NotFocused`（窗口非 key window / 元素未聚焦 / 文本目标无选区：拒绝且未派发任何事件）。文本载荷按字符计 1..=4096（`MAX_TARGETED_TEXT_CHARS`）且无控制字符（控制字符是按键不是文本），kind 映射 `NativeActionKind::TargetedKeys` 过同一能力闸。macOS 后端新增 `MacosNative::targeted_input`（CGEventPostToPid 路线）：取消谓词 → 派发侧台账授权（沿用 CU-06 单次凭证，一次消费恰放行一次派发尝试）→ 载荷校验 → 进程实例 → 身份绑定 → 能力闸族半（Chromium 族后台静默丢弃键事件，零 AX 接触即拒，永不回退 session tap 或全局注入）→ Accessibility preflight → 存活 + 代际（同一 deadline）→ 窗口解析 → 能力闸最小化半（实读 AXMinimized：AppKit 最小化窗口同样静默丢弃）→ 同边界重走复核树版本 → 路径存在性复核 → 子索引路径重解析 → 安全输入框拒绝 → 键盘目标复核（窗口 AXMain 与元素 AXFocused 任一非 true、或文本目标无 AXSelectedTextRange 即 `NotFocused`，只读复核、绝不 mutate 目标状态——后台键事件落在 key window 的焦点视图，否则无法归因到绑定元素）→ 取消复查 → 事件计划投递。投递计划：文本按 UTF-16 ≤10 单元分块且绝不劈开代理对；按键是 down+up 平衡组；修饰键按下 / 释放为 flags-changed 事件带累积 / 递减掩码；平衡步骤间检查取消、目标存活与绑定复核（窗口代际主动证明 + AXMinimized + 元素 AXFocused，各次复核独立 250ms 有界、任何疑点 fail-closed 停止输入——进程活着不等于绑定活着）并以 6ms 步进；修饰键的释放事件在按下投递前预建持有，中止时投递持有的释放（清理只投递从不创建、不被任何后续失败阻断，且只释放本次实际投递的按下状态），零投递零按下的创建失败返回明确错误而非 Partial。生产 native 接线见下文 CU-10 记录；真实验收与各 CU 既有探针结果分开。

CU-08 起落地后台定向指针动作的契约边界与窗口移动。CU-01 实测 CGEventPostToPid 指针事件在 AppKit / Electron / Browser 三族后台全部无效（点击后 caret 不动、按钮不触发），契约层因此只提供明确的拒绝入口：`PointerAction`（Click / Drag / Scroll，坐标为观测换算后的窗口点）在后端派发前于能力闸终态拒绝（Pointer 全族 Unsupported）——零事件、零 AX 接触、无自动重试、永不回退移动物理指针或前台激活；目标内 move 未证明无干扰，不进入词汇。窗口移动是唯一已证明可后台落地的指针族动作（CU-01：AXPosition 写在遮挡的 AppKit 窗口生效）：`WindowMove` 经 `TargetRegistry::consume_window_dispatch`（窗口绑定保持长活、每次派发独立消费并铸单次 `DispatchPermit`）与 `MacosNative::move_window` 的 AXPosition 写路线落地，门序与 CU-06 / CU-07 同族（取消 → 派发凭证单次 armed → 载荷校验 → 进程实例 → 身份绑定 → 能力闸族半（Chromium 系忽略 AXPosition，零 AX 接触拒绝）→ Accessibility preflight → 存活 + 代际（同一 deadline）→ 窗口解析 → 实读 AXMinimized 的最小化半（未知状态 fail-closed 拒绝、不默认非最小化；CU-01 未测最小化移动，Unverified 与 Unsupported 同拒）→ 取消复查 → armed AXPosition 写，返回码单独定终态），终态复用 `SemanticOutcome`（`Dispatched`：AX 调用返回成功，派发证明非效果证明，须以新观测或目标侧事实复核；`UnknownEffect`：messaging 超时，移动可能已生效，不盲目重试）。`spend_for_element_dispatch` 泛化更名 `spend_for_dispatch`（一次消费恰放行一次派发尝试，元素与窗口派发共用同一凭证纪律）。生产 native 接线见下文 CU-10 记录；真实验收与各 CU 既有探针结果分开。

CU-10 起隔离桌面动作与新观测合成一次有界调用：输入动作在派发成功后于同一 `execute` 内捕获新观测并登记新租约（`capture_observation` 与 screenshot 动作共用同一捕获路径：generation 推进作废待用租约、帧必须与连接身份一致、存租约前复核原所有权与原代际；输入路径另带派发代际锚点 `dispatch_generation`，锚点核对与 generation 推进在同一临界区——最后一个输入事件后发生 release、同 scope 排队调用重认领时，旧调用不采用新代际签发租约，而是保留派发事实按观测失败返回），`Output` 显式携带 `input_dispatched`（派发事实，非效果证明）与 `observation_failure`（后置观测失败原因）。后置捕获失败不抹掉已发生的输入：调用仍成功返回、`input_dispatched=true`、观测缺席并记录失败原因，同一调用内不自动重试；取消、后端失败与所有权撤销在捕获路径的既有语义不变（叠加取消释放占用）。动作前观测的单次消费与 scope 校验保持：消费尝试即烧毁租约，新观测是唯一可派发租约且同样单次。生产 native 接线见下文 CU-10 记录；真实验收与各 CU 既有探针结果分开。
CU-17 起本包进入 App 生产依赖图；CU-10 native 将旧 GUI-only 注册表改为 `AppCore::native: Arc<dyn NativeControl>`，模型、GUI 与父子 Core 共用 registry / backend / 窗口代际。Host 承接发现、待批请求、明确授权后绑定 / 启动、截图、读树 / 查元素、语义 / 定向输入与窗口移动，动作后观测沿 tools → Engine 既有持久消息链。CU-03 补同应用多窗口选择：bind / launch 在唯一活实例内为每个窗口签发 Host 句柄，模型明确回传某个句柄；动作后的观测按该窗口身份精确绑定，不从 GUI 目标汇总行挑窗口。网站 current_origin 无信号与 Pointer 三族 Unsupported 保持 fail-closed，不提供全局 / 前台输入回退。离线回归不等于真实 native / GUI / Provider / 用户并发验收，真实环境见 [ENV-08](../../plan/env-08-macos-real-system.md)。

## 3. 对外 API 面

CU-26 `wayland` 对外面（Linux，尚无生产消费者）：`display_socket(display, runtime_dir)` 按 `WAYLAND_DISPLAY` / `XDG_RUNTIME_DIR` 解析 socket，未设置即 `NoDisplay`，不默认 `wayland-0`。`WaylandSeat::connect(socket, settle)` / `connect_from_env(settle)` 先完成 registry 往返与协商：wl_shm、wl_seat、wl_output、screencopy、virtual pointer、virtual keyboard 必须各恰好一个，版本取 min(公告值, 已知值)，缺失或重复返回 `Globals`，此时尚未 bind 任何对象；输出须有当前 mode 且 scale=1、transform=normal。随后为该 seat 创建一次虚拟指针与虚拟键盘、上传 keymap，并等待 `settle`（`DEVICE_SETTLE` 1 秒，CU-23 实测设备新出现后早发事件会丢）。`output_size()` 是指针坐标空间。`capture() -> SeatFrame { width, height, rgb }`；`SeatFrame::jpeg()` 输出最长边 ≤1280、≤512KiB 的 JPEG。`click(x, y, PointerButton, cancelled)`、`key(SeatKey, SeatModifiers, cancelled)`、`type_text(text, cancelled)` 返回 `InputOutcome::{Dispatched, Partial { steps_sent }}`。每个字符发出后，若 `PAWORK_WAYLAND_STEP_DELAY_MS` 为 1..=1000 则等待该毫秒数，否则等待 0；等待不增减事件，只让中途取消检查在真实 compositor 上可观察。`sway::SwayIpc::{connect, connect_from_env, compositor, request, windows, require_dedicated}`，`require_dedicated` 返回实际检查过的输入设备 identifier；`sway::{SwayWindow, SwayRect, CompositorInstance, WindowLedger, process_start}`。`SeatError` 区分 NoDisplay / Io / Protocol / Compositor / Globals / NotDedicated / Capture / Input / Ipc / Cancelled。

CU-06 语义动作对外面（契约 + macOS 后端，生产 Host 经内部 detached 接缝调用，公开授权包装供验收）：`SemanticAction` 三变体——`Press`（AXPress）、`SetValue(String)`（AXValue 整值替换）、`InsertText(String)`（AXSelectedText 选区替换，塌缩选区即插入）；`kind()` 映射 `AxPress` / `AxSemanticWrite` 并过同一 `require_background` 闸，`validate()` 按字符复核 4096 硬上限（空串合法即清空）。`MacosNative::semantic_action(authorizer, validated, path, action, cancelled)` 门序：取消 → 派发侧台账授权（`consume_dispatch_permit`：把消费时铸的单次票据标记 armed，再次消费拒绝；NativeHost 核对原台账代次并在平台调用后退役，撤销 / 重授作废在途票据，克隆消费结果无法二次派发）→ 载荷校验 → 进程实例 → 身份绑定 → `require_background` 能力闸（先于一切 AX 接触，Chromium 族语义写在此零接触拒绝——CU-01 实测其 success 但无效）→ Accessibility preflight → 存活 + 代际 → 同边界重走复核树版本（不一致 TreeChanged）→ 路径存在性（不在按 Invalid）→ 逐级 armed 有限切片重解析（缺序 TreeChanged、null 洞 ProbeUnavailable）→ 写类 `refuse_secure_write`（重读 role/subrole，识别失败保守按敏感，安全输入框 Invalid 拒）→ 取消复查 → armed 单次 AX 调用；返回码定终态：0 → `Dispatched`（派发非效果证明，须以新观测或目标侧事实复核），-25204 → `UnknownEffect`（可能已生效，不盲目重试），-25205 / -25206 → `ElementUnsupported`，-25202 → TreeChanged，-25211 → PermissionMissing，其余保留原因 ProbeUnavailable。同一 deadline（`AX_TREE_BOUNDS.max_read`）贯穿存活证明、窗口解析、版本复核、路径解析与动作调用；能力闸不查最小化态（两种语义 kind 在 CU-01 矩阵中最小化不变，回归钉住）。

CU-08 指针与窗口移动对外面（契约 + macOS 后端，生产 Host 经内部 detached 接缝调用，公开授权包装供验收）：`PointerAction` 三变体——`Click { point }`、`Drag { from, to }`、`Scroll { point, delta_x, delta_y }`（坐标为观测换算后的窗口点）；`kind()` 映射 `NativeActionKind::Pointer`，`validate(window_width, window_height)` 复核坐标有限且在 `[0,width) × [0,height)`（与 `image_to_window` 同一边缘不含语义）与滚动增量有限。`MacosNative::pointer_action(authorizer, validated_observation, action, cancelled)` 门序：取消 → 台账复查（观测消费为 plain spend 无凭证，消费后撤销在此阻断）→ 载荷校验 → 进程实例 → 身份绑定 → 能力闸终态拒绝（Pointer 三族全 Unsupported，`BackgroundUnsupported`，零事件零 AX）。`WindowMove { x, y }`（`kind()` 映射 `WindowMove`，`validate()` 仅有限值）；`TargetRegistry::consume_window_dispatch(window, scope, cancelled) -> ValidatedWindowDispatch`（窗口绑定长活非租约：取消 → 存在性 → Scope → 授权 → 占用 → UserActive → 存活 → spend + 铸单次 permit → 刷新占用）；`MacosNative::move_window(authorizer, validated, origin, cancelled) -> SemanticOutcome` 门序见 §1，AX 返回码映射复用 `semantic_action_result`（0 → Dispatched、-25204 → UnknownEffect、-25205/-25206 → ElementUnsupported、-25202 → TreeChanged、-25211 → PermissionMissing），AXValueCreate 失败按 ProbeUnavailable 拒。

CU-10 native 入口：`NativeHost::new(surface)` / `host()`、open_scope / close_scope / grant / revoke / grant_kind / target_states / active_scopes / wait_for_requested_grant / execute；`NativeControl` 将同一控制面与 NativePerform 执行面共享给 Core。请求只登记选择、不产生 grant；状态聚合 requested ∪ grants ∪ 绑定，child 不继承父 scope 授权。CU-18 增 `note_requested_application`：仅把已构造应用身份写入同一 registry 的 requested 集，不解析 bundle、不启动进程、不绑定窗口、不调用 probe、不签授权；生产 tool dispatch 仍经原 request/bind/launch 解析与授权闸，该接缝用于 UI fixture / 测试构造待批目标。CU-03 多窗口 bind / launch 复用现有 action、审批等待和 registry，输出只列 `Host句柄 宽x高`，无默认 `window_id`、无标题 / PID / 原生窗口 ID；单窗口输出不变。`bind_window_with` 在原授权、占用、进程与 origin 闸通过后才复用已有句柄，内部 `issued_window` 精确匹配 target / scope / instance / window（含代际），同时用于动作后观测回查。GUI 每目标仍只有一行窗口字段，按句柄字典序选展示代表，不作为操作选择入口。动作消费在原 registry 将本次 ticket 标记 armed，`inflight_current` 核对 scope / target / 原台账代次，平台调用返回后 `retire_inflight`；撤销、关闭或重授不能复活旧票据，取锁失败 fail-closed。长 AX 后、不可回退调用前及定向事件组间重新读取 target activity，Operating / Unprovable 时让出。Dispatched / Partial / UnknownEffect 的后置观测失败保留派发事实，不自动重试，Once 不为新观测额外续授权；read_tree 的普通 Text 包含节点与截断。macOS 信号只读 frontmost bundle、不记录全局键盘内容；真实接管及时性与连续用户输入待 [ENV-08](../../plan/env-08-macos-real-system.md)。

## 4. 关键行为与语义

CU-10 本轮等批接缝（2026-10-09，本轮模拟验证与独立 R3 review PASS）：`NativeControl` / `NativeHost::wait_for_requested_grant(scope, bundle_id, cancelled)` 仅对活跃 scope 内恰好一条同 bundle requested target、且当前缺授权的情况等待；其它情况立即返回，由后续 bind/launch 解析终态。Condvar 使用原 registry 锁的真实谓词循环，等待释放锁；grant / revoke / close_scope 唤醒，取消每 250ms 复查。撤销同时移除对应待批请求，避免再次睡回原请求。该接缝不签授权、不克隆许可，不放宽原授权代次与一次派发凭证。

桌面以会话为所有权边界（CU-09）：一个桌面同时只属于一个 workspace/run，非拥有 Run 的任何动作（含 status）按 Error::Conflict(owner) 立即拒绝、零后端访问；取消/超时释放占用并作废待用观测，空闲超过 OWNERSHIP_TTL（60 秒，与观测租约同寿）自动失拥有，宿主用 Computer::release(scope) 在 Run 终止时显式释放。坐标从 JPEG 左上角开始，严格在 `[0,width) × [0,height)`，按虚拟尺寸缩放。截图最长 1280、≤512 KiB；raw framebuffer 单边 ≤4096、总像素 ≤8M，响应字节、矩形、消息与 8 秒 I/O 均有上限。每次全量截图覆盖全部像素后才返回，禁止残帧伪装截图。观察绑定 scope、连接身份和尺寸，60 秒失效；输入前即消费，错误不允许重用。断线后新连接身份使旧观察失效；不自动重试输入。取消/错误时尝试释放，传输失败断开由 Xvnc 释放客户端状态。成功仅代表投递（CU-10 起输入结果随附动作后新截图供直接核对；观测失败时输入事实保留，效果以再次截图核对）。

target 契约沿用并细化同一租约模型：观测与元素句柄 60 秒 TTL、一次性消费——消费元素同时作废父观测与兄弟元素句柄；校验通过即消费，后续派发失败不回收。观测/元素消费按固定顺序校验：取消 → 存在性（伪造/未知 → UnknownHandle，宿主重启后全部旧句柄落入此类）→ Scope（跨 Run / 跨 workspace → CrossRun）→ 过期或已消费（StaleHandle）→ 授权（未授权或撤销 → NotAuthorized，受保护目标 → ForbiddenTarget）→ 占用（CU-09：应用的占用 Run 已易主 → TargetOccupied）→ 接管暂停（UserActive）→ 进程实例（退出或重启 → ProcessRestarted）→ 窗口代际（销毁或标识符复用 → WindowReplaced）→ AX 树版本（树前进 → TreeChanged，AX 观测消费与元素句柄同校，截图观测不受树变化影响）→ 观测尺寸（变化 → StaleHandle，不可得 → WindowReplaced）；坐标非有限值或越出图像边界（含边缘本身）→ OutOfBounds。元素句柄只能由 AxTree 观测签发。后台能力以 CU-01 实测为唯一依据：仅 Supported 放行，Unsupported 与 Unverified 同拒（BackgroundUnsupported）且永不回退全局输入；指针动作三类应用族后台一律拒绝；AppKit 定向键在窗口最小化时拒绝；AppKit AXPress 与最小化态窗口移动/缩放未单独实测，按 Unverified 拒绝。用户接管同一目标没有系统级仲裁（CU-01 T6b）；CU-09 起由宿主信号承接：pause_dispatch 后派发闸按 UserActive 让出且不消耗租约（授权检查后、probe 之前拒），resume_dispatch 恢复后未过期租约可继续派发；宿主无法判定用户意图时保持暂停（fail-closed），不与用户竞争。目标占用按应用 anchor 单占用：bind 在存活与 origin 校验全部通过后才认领（失败绑定不留占用）、观测 / 校验 / 派发刷新或拒绝，release_scope / revoke / revoke_scope 释放，占用者空闲 60 秒自动失效。

CU-16 起校验链在 StaleHandle 之后、进程实例 probe 之前插入授权裁决：绑定、观测签发、窗口校验与动作消费均先查 `(Scope, TargetIdentity)` 授权（无授权 / 已撤销 / 跨目标 → NotAuthorized，受保护 bundle → ForbiddenTarget），台账拒绝零 probe 调用（回归以计数钉住）；宿主捕获前预检 `require_authorized` 同序执行——先查台账、再过占用闸（占用已易主 → `TargetOccupied`，先于任何 probe）、再复核网站目标当前 origin，跨源或 origin 不可得即 SiteChanged，拒绝时宿主不得连接 / 捕获 / 读取目标；预检与窗口校验均不刷新占用活跃（刷新只在 bind 认领与 begin / consume 成功使用）；真实平台后端的捕获 / 输入访问以该预检接线为前提，随 CU-03+ 落地后验证。once 授权只在其余校验全部通过后、动作真正放行时才消耗——绑定需要有效授权但不消耗，陈旧目标或拒绝路径不烧掉用户的单次批准；一次观测或一次输入各为一个动作。元素句柄签发不重复查授权（其父观测已带授权），撤销在观测与派发之间到达时由 `consume_observation` / `consume_element` 的先于 probe 复查阻断。授权只覆盖被批准目标：整应用授权不覆盖其内任何网站，单源网站授权不覆盖浏览器与其它源；网站目标在绑定与每次 live 校验时经 `NativeProbe::current_origin` 复核窗口当前 origin（归一化比较，尾斜杠 / 大小写 / 端口拼写不能绕行），同窗口跨源导航或 origin 不可得一律 SiteChanged，先于派发拒绝。身份在授权入口统一 `validate` 复核，公开枚举与反序列化不能绕过构造校验。授权仅存内存，随 run 结束（`revoke_scope`）或 Host 退出消亡；已执行动作是历史，撤销不回写。


CU-03 macOS 后端把契约接缝落成真实平台信号。进程实例 = pid + `kern.proc.pid` sysctl 启动时间（微秒；只读 kinfo_proc 头部 16 字节的 start timeval，不依赖内核版本相关的完整结构布局）+ NSRunningApplication `isTerminated` 终止态：PID 复用或进程退出后旧实例永不判活。窗口代际账本随窗口服务器快照同步：新见到的窗口 id 分配新代际，快照中消失的 id 被遗忘，id 复用时拿到新代际；枚举、账本同步与代际提取在同一把互斥锁内完成，旧快照永远覆盖不了新账本，每个给出的代际都来自它被核验的那次快照（绑定与校验共用同一 `MacosNative` 实例的克隆）。窗口存活是双条件：CGWindowList 在册 **且** 应用自身 AXWindows 证明其存在——macOS 已关闭窗口会在窗口服务器列表长期残留（幽灵项，属性与活窗一致，TextEdit / Terminal 实测），单凭在册不能证明存活。对应关系两级：`_AXUIElementGetWindow`（HIServices 私有导出，yabai / Hammerspoon 等同族依赖）可用时把 AX 窗口映射到窗口服务器 id，幽灵 id 永不映射——同帧关窗只失效自己，幸存同帧窗继续有效（定向回归与真实验收双重钉住）；该导出缺失或失败时退化为帧组闭合——同帧窗口服务器计数等于 AX 计数才判活，幽灵只 inflate 服务器侧，任何一侧多余即歧义 fail-closed，且组内任一 AX 窗口若同时匹配组外 CG 窗口（epsilon 匹配不可传递，一个 AX 候选可落进两个帧组）同样歧义拒绝——重叠下同帧幽灵会连带失效幸存窗直到幽灵被回收，文档化且仍然安全。读取授权另受身份-进程绑定约束：list_windows 在 AX / 标题访问前经 NSRunningApplication 回读 pid 的 bundle id 比对获授权身份，错配按 Invalid 拒绝。Accessibility 权限缺失时授权窗口路径按 `PermissionMissing("accessibility")` 拒绝；权限在而 AX 调用失败按 `ProbeUnavailable` 拒绝（错误码保留在消息里，kAXErrorAPIDisabled=-25211 仍归权限类，CannotComplete=-25204 等其余码归 probe 失败；HIServices 符号缺失的预检失败同样归 ProbeUnavailable 而非误报缺权限）；`window_generation` 对任何失败一律 None（fail-closed）。受控启动恒用 `NSWorkspaceLaunchWithoutActivation`（0x200），不激活、不夺焦点；授权检查先于 LaunchServices（回归以启动缝调用计数钉零），bundle id 解析不出已安装应用按 NotFound 拒绝，启动后读不到实例令牌按 ExitedEarly 拒绝。族分类是启发式：声明 http/https URL scheme → Browser（Chromium / WebKit / Gecko 内核均覆盖），捆绑 Electron / Chromium Embedded Framework → Chromium，其余 → AppKit，只喂 CU-01 能力矩阵。系统权限只读预检（ScreenCapture preflight + AXIsProcessTrusted），任何路径都不发起 TCC 请求。链接细节：AppKit 经空 extern 块强制链接以加载 NSWorkspace / NSRunningApplication 类，HIServices 沿用 CU-01 的 dlopen 模式。

CU-04 窗口截图沿用同一诚实性纪律。捕获门序固定为台账授权 → 进程实例 → 身份绑定（bundle id 系统回读，错配按 Invalid 先于 AX 读取拒绝）→ 窗口存活 + 代际（复用 CU-03 同一快照证明）→ Screen Recording preflight → SCK 捕获缝，任一前置失败时捕获缝零调用；Screen Recording 缺失按 `PermissionMissing("screen recording")` 在捕获前拒绝，任何路径不发起 TCC 请求。SCWindow 按窗口 id + 属主 pid 双因子定位；捕获与存活证明之间关窗按 WindowReplaced，其余捕获失败保留 OS 原因按 ProbeUnavailable；每次捕获都是全新单帧且 `scalesToFit` 铺满配置帧（内容恒覆盖全图），completion handler 10 秒超时，无旧图 / 残帧 / 部分数据路径。completion 状态机是显式所有权：超时先标记 abandoned，迟到回调由 handler 侧立即释放已 retain 对象，结果恰在超时与加锁之间落盘时由等待方释放，结果与错误同时到达时由 deliver 统一释放——错误交付永不携带已 retain 指针，filter / config 在超时、错误、nil 全路径释放——任何路径都不泄漏对象或迟到帧。图像管线三级收口：`capture_scale` 在 ≤2x 内再受单边 ≤4096、总像素 ≤8M 约束（不满足即拒绝，不降级放大），`capture_pixel_size` 逐轴 floor 并复核整数乘积（独立四舍五入可突破预算），`checked_frame_layout` 在复制实际像素前对交付帧复核同一预算；BGRA→RGB 逐行 stride 校验，截断 / 不一致拒绝；基线 JPEG 最长边 ≤1280、字节 ≤512KiB（质量阶梯 75/50/30，与隔离桌面同口径）。观测记录捕获时窗口点尺寸，`begin_observation` / `consume_observation` / `consume_element` 在树版本校验后与 `window_size` 实时值比对（±0.5pt，同后端帧容差）：缩放即 StaleHandle（重新观测恢复，窗口绑定不受累），恢复尺寸后在途租约可放行，尺寸不可得按 WindowReplaced fail-closed；坐标映射不变——`image_to_window` 把模型图像像素换算为窗口点（真实验收：833×529 窗口的图像中心点精确映射 (416.5, 264.5)）。截图不激活目标、不动前台与焦点（front_unchanged 真实验收钉住）。

CU-05 有界树读取沿用同一诚实性纪律。读树门序固定为台账授权 → 进程实例 → 身份绑定 → Accessibility preflight → 窗口存活 + 代际 → 遍历缝，任一前置失败时遍历缝零调用（回归以计数钉住）；Accessibility 缺失按 PermissionMissing 在内容读之前拒绝，AX 调用失败保留原因按 ProbeUnavailable，两者都拒绝访问。遍历有界：深度、节点、文本截断是确定性的、在读取上置标志；时间预算（10 秒）是同一 deadline 贯穿窗口解析、读使能与遍历，每次 AX 调用以该次调用开始时的剩余预算为逐元素 messaging timeout、返回后复核时钟、交付前最终复核，超支整读失败——超时部分树既不能支撑稳定版本也不能支撑可证查找。结构一致性：已上报正子数的元素，其子列表缺席 / 失败 / 数量不足 / 含空指针一律拒读。名称读取失败（真实应用存在，TextEdit 文本区 AXDescription 返回 kAXErrorFailure）不伪装不匹配：置节点 name_unreadable 与读级 names 标志。读失败是 TargetError，成功读 nodes[0] 恒为窗口根：根无子是「应用未暴露元素」的肯定答案，空树永不伪装读失败。树版本是一次有界读的 64 位 FNV-1a 指纹（同树同边界同版本；帧为窗口本地坐标，纯移动不推进版本，缩放 / 布局变化推进），消费元素句柄或 AxTree 观测时后端以同一边界重走复核；指纹是非加密散列——理论碰撞存在，作为廉价变更信号而非防篡改证明。元素查找永不歧义取第一：多匹配按 Ambiguous（带已读部分匹配数）；唯一匹配的可证性精确到判据——深度 / 节点截断使一切查询不可证（UnprovenUnique 不签发），文本截断与名称不可读只使含名称条件的查询不可证，角色单条件查询在结构完整读上仍可签发；零匹配带 tree_truncated 区分「完整树上不存在」与「未读部分未知」。敏感边界：元素内容（AXValue）永不读取；安全输入框按 subrole 识别（AXTextField + AXSecureTextField；识别失败保守按敏感），连名称都不读，读树顺势获取密码 / Token / 文档正文的路径不存在。Chromium 族读使能：每次读树前在应用元素 best-effort 设 AXManualAccessibility（VoiceOver 同款，幂等、不改 UI）；渲染进程异步物化树（真实验收实测约 1–2 分钟），全新 Chromium 窗口首读可能如实只含窗口铬，后续读收敛到完整树——「此刻只暴露这些」是肯定答案而非错误。

## 6. 红线与不变量

CU-21 Host 固定连接 `127.0.0.1:5906`，guest 在容器内监听 `0.0.0.0:5906`，compose 仅发布到宿主 loopback；RFB 连接保持 `127.0.0.1:5905`。`PAWORK_ISOLATED_GUEST_TOKEN` 至少 16 个非空白字节。token 仅校验客户端共享秘密，不证明双向认证，容器隔离与 loopback 部署仍是前置。发现元数据不含标题或 AT-SPI 树；目标内容读取须经原授权闸。窗口身份包含 PID / 启动令牌、窗口代际和 guest 进程/连接代次；读树以具体窗口为根，元素沿用树版本与子路径。捕获裁剪前后复核身份、几何与遮挡，无法归属到该窗口时拒绝。已发送按压请求后回执丢失保留 UnknownEffect，不自动重试；真实拒绝与停止证据见本项计划。

CU-26 seat 客户端不变量：
- 只连专用 seat，不碰宿主主 seat，不回退 XTEST，不走 portal。
- 三条协议的权限来自 socket 可达性、作用于整个 seat。`require_dedicated` 要求恰好一个 `HEADLESS-*` 输出、一个 seat，输入设备只允许 `0:0:wlr_virtual_pointer_v1` / `0:0:wlr_virtual_keyboard_v1`；客户端侧另拒多 seat、多输出。它只能在调用时发现问题，无法阻止同 guest 内其它客户端用同一 socket，所以部署必须独占 guest，sway 配置不带按键绑定。
- 窗口身份只取 compositor 数据：pid 来自 Wayland 客户端凭证，进程实例 = pid + `/proc` 启动时间，代际按 (compositor 实例, con id) 记账；compositor 重启后旧代际全部失效。Xwayland 窗口与缺 pid / app_id 的 toplevel 一律拒绝。
- 截图每次都是新 shm buffer 的完整帧，`failed`、未知像素格式或越界尺寸都返回错误，不返回旧帧或残帧。
- 文本整段先校验，越出 keymap（非 ASCII、控制字符）时零事件拒绝。按下之后必定发送释放，修饰键状态在按键后清零。sync 往返只证明事件已送达 seat，不证明目标效果。
- 切片 2 guest 服务：每次操作都重做 `require_dedicated` 与窗口解析；返回给 Host 的代际混合 ledger 代际、compositor 实例、连接 epoch 与进程 nonce。目标不可见、超出唯一输出或与其它可见窗口重叠时，截图和输入都拒绝。截图前后各解析一次，变化即拒绝，裁剪只取窗口 rect。文本 / 按键要求 compositor 焦点在目标窗口，guest 从不移动焦点。动作前 Host 已断开则零事件；seat I/O 失败报回执丢失。
- 切片 2 Host：`WaylandSurface` 在 guest 回包前后各复核身份、可见与无重叠，回包身份 / 几何必须等于前置值，JPEG 必须可解码、尺寸一致且在预算内。能力闸只放行 CaptureWindow / Pointer / TargetedKeys。`ObservedClick` / `ObservedKeys` 的载荷闸（`admit_observed`，默认拒绝）与坐标越界都先于租约与授权花费；消费后只放行一次 armed 派发，派发期间撤销 / 关闭 / 取消即停。Partial 与 UnknownEffect 保留派发事实、不自动重试，动作后观测失败不抹掉派发。端口固定为 loopback 5907，模型不能传端口、路径或 pid。`resolve` 不把可恢复的连接或元数据错误收成「未安装」：非 `guest.wayland.` 前缀，或元数据成功但没有该 bundle，才是未安装；`Disconnected` 重拨一次，仍失败或元数据 `Unavailable` 为 `ProbeUnavailable`；目标批准仍是之后的 `NotAuthorized`。
- 2026-10-15 部署复审：`network none` 与「把容器 5907 发布到宿主 loopback」不能同时成立。本盒宿主 `127.0.0.1:5907` 已被 x11vnc 占用，验收不得改掉它。当前容器形态保持 network none（guest 仍听容器内 `0.0.0.0:5907`，只有 lo），唯一宿主挂载是控制用 Unix socket 目录；Host 探针在另一个 netns 里把 `127.0.0.1:5907` 转到该 socket。这不是 CU-23「无宿主 bind、无端口映射」的全文。

遮挡枚举不以窗口尺寸或 WM_CLASS 过滤；属性 / 树读取失败、枚举超过 4096 个窗口时拒绝，几何不明保守拒绝。QueryTree 的 parent 字段与 root 分开解析，短 children 回包拒绝。Host 沿实际父链排除目标自身的框架与内容，下降遇其它获准 client 或已知 stacking 的 rejected client 停止；非自身重叠窗口任一侧 stacking 未知时拒绝。已发送 `DoAction` 的 NoReply、I/O、Timeout、Disconnected 或无效回执保留 UnknownEffect；明确 false、未知方法 / 接口、不支持、参数及访问拒绝不当作回执丢失。

Pawork 集成通过 [tools](tools.md) 复用 ExternalPlugin / requires_approval / untrusted 与 ReadOnly 拒绝；构造不触网，审批在连接前。固定 loopback 端口、RFB 3.8、桌面名匹配只是配置检查，不是远程身份认证或隔离证明；部署必须使用所附虚拟桌面，不转发物理屏幕。容器不挂载宿主目录/设备/桌面/剪贴板，只发布 loopback 端口，拒绝第二个 viewer。服务器 None 认证仅限这个本地部署。环境缺失/断线直接失败，没有回退本机路径。截图为未信任数据，仍持久化并发送给模型，不提供通用视觉脱敏。应用焦点变化仍需新截图验证；隔离解决本机输入争抢，不保证容器完全不消耗宿主资源。

target 契约层不变量：契约代码不调用任何平台 API（活跃状态经 `NativeProbe` 宿主注入）；句柄只能由 `TargetRegistry` 签发，模型输入永远按未知句柄拒绝兜底；无后台实测支持的动作直接拒绝，不存在全局输入、前台激活或事后恢复状态的隐式降级。

审批契约层不变量（CU-16）：授权只能由宿主在显式用户审批后签发——模型侧只能触发检查，永不能签发或扩大授权；自动审批 resolver 不能满足 Policy AskUser，因此永远产生不了授权，不另造审批框架。台账授权拒绝（NotAuthorized、ForbiddenTarget）先于一切 probe 调用（回归以 probe 调用计数钉住）；SiteChanged 裁决须经 `current_origin` 接缝（不触碰进程实例与捕获后端）；CU-10 接线复用 tools Policy / 显式审批与 Host 目标授权两层闸门，离线验证与真实平台验收分开。`MINIMUM_PROTECTED_BUNDLES` 内置 Pawork 自身 UI 与 macOS 权限界面（大小写不敏感、宿主只能加不能减、默认构造即生效）：受保护目标永不可授权、永不可绑定，Agent 无法经 Pawork 审批界面或系统权限界面自我批准；契约不存在任何变更 OS Screen Recording / Accessibility / Automation 权限的 API，系统权限缺失只能如实报告。网站目标 origin 不可得即 fail-closed（SiteChanged）。逐目标持久授权不存在：持久允许仅走已裁决的 ApprovalMode / workspace trust 设置口径，新增逐目标持久授权须先过 ADR。


macOS 后端不变量（CU-03）：启动只接受 LaunchServices 可解析的 bundle 身份，不存在任何可执行路径入参；授权裁决先于一切系统调用——未授权、已撤销、跨目标与受保护目标在触碰 LaunchServices 之前即拒绝（回归以启动缝调用计数钉零）。启动恒不激活、不夺焦点（`NSWorkspaceLaunchWithoutActivation`）；发现与列举全程只读。读取授权闸：`list_windows` 先核验 (scope, 目标) 授权再碰 AX 树与标题，未授权读取连一次 AX 调用都不发生；授权身份与进程绑定——AX / 标题访问前回读 pid 的 bundle id 比对获授权身份，错配按 Invalid 拒绝；标题按 owner pid 门控，只复制获授权目标自身窗口的标题，其它应用的标题从不进内存；发现路径（`list_applications`）不读标题、不读 AX 树，窗口计数是窗口服务器元数据（可能含幽灵）。窗口标题是内容，仅在授权调用显式 `include_titles` 时才从窗口服务器字典复制出来（没有 Screen Recording 权限时系统本就不给标题）。`permissions()` 只读 preflight，任何路径都不触发 TCC 弹窗、不变更系统权限。窗口存活以「窗口服务器在册 + 应用自身 AXWindows 证明」双条件判定：`_AXUIElementGetWindow` 可用时按窗口服务器 id 精确对应，缺失时帧组闭合（计数相等且组内 AX 候选不跨组重叠，否则拒绝）、歧义 fail-closed；AX 不可得一律 fail-closed，绝不凭 CGWindowList 在册单独认定存活（已关闭窗口在那里长期残留为幽灵）。`tree_revision` / `current_origin` current_origin 没有信号源就报不可得，网站目标随之 fail-closed，不静默信任无法复核的状态；tree_revision 自 CU-05 起有真实信号源（同边界重走指纹，任何失败 None fail-closed）。窗口代际的枚举、账本同步与提取在同一把锁内完成，旧快照永远覆盖不了新账本；账本只由同一 `MacosNative` 实例的克隆共享。

CU-04 截图不变量：捕获门序（台账授权 → 进程实例 → 身份绑定 → 存活 + 代际 → Screen Recording preflight）任一拒绝先于捕获缝生效（回归以捕获缝调用计数钉零），权限缺失永不在捕获后才报告；获授权身份与实例进程错配在任何 AX 读取前按 Invalid 拒绝——一个应用的授权永解不开另一个进程的窗口。不存在旧图 / 残帧 / 部分像素返回路径，失败必带真实终态（WindowReplaced / ProbeUnavailable / PermissionMissing）；窗口内容恒铺满输出帧，不存在黑边伪装截图。completion 超时、迟到回调与「错误伴随结果」全路径释放已 retain 对象（错误交付永不携带所有权），filter / config 在超时、错误、nil 全路径释放，无泄漏路径；整数输出尺寸逐轴 floor 并复核乘积，交付帧在复制像素前复核预算，取整永不突破上限。窗口缩放即观测失效，契约不存在跨尺寸坐标复用；截图永不激活目标、永不改变前台与焦点，永不发起 TCC 权限请求。

CU-05 有界树不变量：读树门序（台账授权 → 进程实例 → 身份绑定 → Accessibility preflight → 存活 + 代际 → 遍历缝）任一拒绝先于遍历缝生效（回归以计数钉零），未授权读树连一次 AX 内容调用都不发生。元素内容（AXValue）永不读取；安全输入框按 subrole 识别（AXTextField + AXSecureTextField），识别失败保守按敏感不读名——读树路径不存在获取密码、Token 或文档正文的可能。树读取恒有界（深度 / 节点 / 文本 / 时间），时间预算是贯穿窗口解析、读使能与遍历的同一 deadline，每次 AX 调用以该次调用开始时的剩余预算为逐元素 messaging timeout 并复核返回时钟、交付前最终复核，符号缺失或超时设置失败拒读，超支整读失败而非返回部分树；结构不一致（子列表与上报计数不符、含空子元素）拒读；名称读取失败不伪装不匹配——置 names 标志使名称查询显式不可证；读失败是错误，成功读 nodes[0] 恒为窗口根，空树不伪装读失败、「应用未暴露元素」只能是肯定答案。树版本是有界读的 64 位 FNV-1a 指纹（廉价变更信号，非防篡改证明），消费时以同一边界重走复核，边界固定不可按调用调。元素查找永不歧义取第一：深度 / 节点截断下唯一匹配按 UnprovenUnique 不签发句柄，名称判据在文本截断或名称不可读下同规，角色单条件查询在结构完整读上仍可签发；NoMatch 以 tree_truncated 区分「完整树上不存在」与「未读部分未知」。Chromium 族读使能（AXManualAccessibility）幂等、不改 UI、失败不拒读；节点序号（path）只是单次读取内的解析线索，不是跨观测稳定身份。
CU-09 所有权与接管不变量：隔离桌面的所有权闸先于一切锁等待与后端访问——非拥有 Run 的任何动作立即 Conflict、零后端调用，不存在排队后拒绝或跨 Run 共享观测；取消 / 超时 / backend 失败叠加取消释放占用并作废待用观测，键鼠平衡仍由 backend 保证；release 推进 generation，在途操作只验证原所有权（空槽 Cancelled、新拥有者 Conflict），不得重新认领；在途输入的取消谓词并入所有权撤销与代际（release 后停止后续事件），在途截图存租约前复核原代际（同 scope 重认领后按 Stale 拒绝）；占用者空闲超过 OWNERSHIP_TTL 自动失拥有，所有权永不长于可用观测。契约层占用以应用 anchor 为单位（网站目标即其浏览器进程），bind 校验全部通过才认领（失败不留占用）、观测 / 校验 / 派发全链刷新或拒绝，第二个 Run 的冲突可见（TargetOccupied）；用户接管是宿主信号（pause_dispatch / resume_dispatch），暂停期间派发闸让出且不消耗租约、观测保持可用，宿主无法判定用户意图时保持暂停不竞争；release_scope / revoke / revoke_scope 释放占用，revoke 保留 CU-16 的 NotAuthorized 阻断语义与已消费历史。后台路径不抢占目标前台、不读系统剪贴板（既有红线），异常状态按真实终态上报。

CU-06 语义动作不变量：能力闸先于一切 AX 接触——Unverified / Unsupported 的族 × 动作组合连一次 AX 调用都不发生（Chromium 语义写实测静默无效，矩阵拒绝是唯一正确行为），不存在全局输入、前台激活或坐标输入回退。动作调用是不可回退点：一旦发起，返回码单独决定终态——成功是 Dispatched（派发非效果证明，目标可接受调用并忽略，须以新观测或目标侧事实复核），messaging 超时是 UnknownEffect（动作可能已生效，绝不伪装成干净失败诱导盲目重试）；元素自身肯定拒绝（ActionUnsupported / AttributeUnsupported）按 ElementUnsupported 如实上报，与能力闸的前置拒绝区分。派发侧授权与消费协调：consume 元素句柄经 `spend_for_element_dispatch` 消费授权并铸单次派发凭证 `DispatchPermit`（进程级 pid+纳秒+序号命名空间保证唯一，随 `ValidatedElement` 携带），后端 `consume_dispatch_permit` 在首次派发尝试原子退役——恰好放行该次消费释放的一次派发，克隆消费结果无法二次派发，观测消费的 plain spend 不产凭证；账本 `TargetAuthorizer` 不派生 Clone（深拷贝会复制未用凭证让一次消费逐副本重复派发、原账本撤销不清副本，编译期断言钉住）；消费后撤销仍阻断派发（revoke / revoke_scope 同清未用凭证），check / spend 的「Once 恰好消耗一次」语义不放宽。取消谓词在入口与不可回退调用前各查一次；调用已发起则取消不再改变终态，Dispatched / UnknownEffect 如实上报。存活证明与树接触共用同一 deadline，存活读取超时保留超时原因而非伪装 WindowReplaced。写类动作永不进入安全输入框（重读 role/subrole 复核，识别失败保守按敏感），与读侧「永不读 AXValue、安全框不读名」对称——输入凭证是用户的键盘，不是后台 AX 写。派发复核与初读共用同一固定边界；树版本不一致或路径失序按 TreeChanged 拒绝，伪造路径形状按 Invalid 拒绝，文本载荷超 4096 字符按 Invalid 拒绝。

CU-07 定向输入不变量：能力闸分两半且都先于事件——族半在任何 AX 接触前（Chromium 族静默丢弃后台键事件，零接触拒绝，永不回退 session tap 或全局注入），最小化半在窗口解析后实读 AXMinimized（AppKit 最小化同样静默丢弃）。键盘目标复核只读 fail-closed：窗口 AXMain 与元素 AXFocused 任一非 true、或文本目标无选区即 NotFocused，绝不 mutate 目标状态（不设 AXMain / AXFocused / 系统焦点）——后台键事件落在 key window 的焦点视图，归因不到绑定元素的输入不发；入口复核在多步输入全程维持：平衡步骤间的绑定复核（代际主动证明 / AXMinimized / 元素 AXFocused）独立有界且任何疑点 fail-closed 停止——进程活着不等于绑定活着，后续步骤不得向已失效绑定继续输入（窗口已关 / 已最小化 / 元素已失焦时继续投递可能落到别的窗口或安全输入框）。事件平衡纪律：每个步骤是平衡组（先建全组事件再投递，创建失败零投递），修饰键的释放事件在按下投递前预建持有——释放承诺由结构保证，清理只投递不创建、不被取消 / 复核失败 / 后续创建失败阻断，且无按下状态时不投任何释放；中止返回 Partial（如实携带已投计数与原因、绝不当作干净失败静默重试），零事件零按下的创建失败是明确错误而非 Partial；Dispatched 只是派发证明（CGEventPostToPid 无回执），效果须新观测或目标侧事实复核。安全输入框与语义写同拒（`element_is_secure` 共用），凭证沿用 CU-06 单次派发纪律（一次消费恰放行一次派发尝试）。

CU-08 指针与窗口移动不变量：指针动作（点击 / 滚动 / 拖动）三族后台一律拒绝且零派发——CU-01 实测无效（caret 不动、按钮不触发）即矩阵唯一依据，不存在移动物理指针、前台激活或事件注入回退，目标内 move 未证明无干扰、不进入词汇；坐标校验先于能力闸（越界 / 非有限值按自身拒绝上报），被拒动作不自动重试可能已派发的任何东西。窗口移动经单次派发凭证（窗口绑定长活，一次消费恰放行一次 AXPosition 写，克隆消费结果无法二次派发，消费后撤销仍阻断）；族闸先于一切 AX 接触（Chromium 系忽略 AXPosition 写，零接触拒绝），最小化半在窗口解析后实读 AXMinimized（未知状态 fail-closed、不默认非最小化；CU-01 未测最小化移动，Unverified 与 Unsupported 同拒），AXValue 经 RAII 恰一次释放（budget 失败路径同样不泄漏）；AXPosition 写是不可回退点，返回码单独定终态（Dispatched 派发证明非效果证明，UnknownEffect 可能已生效不盲目重试）；原点只校验有限值、不做屏幕钳制（负全局坐标是多显示器合法状态，部分离屏是合法用户状态，契约不「纠正」）；移动不读树、不依赖树版本（CU-05：帧为窗口本地坐标，纯移动不推进版本）。

CU-07 增四项定向回归：契约层 `targeted_inputs_validate_and_map_to_the_capability_kind`（kind 映射、字符计上限、空文本与控制字符 Invalid、按键词汇构造即合法）与 `targeted_capability_gate_is_the_measured_matrix`（AppKit 后台过、最小化拒、Chromium / Browser 全拒、菜单快捷键拒）；macos 层 `targeted_event_plans_chunk_on_char_boundaries_and_stay_balanced`（UTF-16 分块不劈代理对、每块 ≤10 单元、修饰键掩码累积按下 / 递减释放、计划事件平衡）与 `targeted_input_authorization_gates_precede_the_post_seam`（伪造凭证 / 超长载荷 / 死进程 / 身份错配 / 凭证二次使用 / 撤销 / 取消分别先于投递缝拒绝、TARGETED_POST_SYSTEM_CALLS 计数钉零，再对本进程 pid 实投验证投递纪律：Dispatched 计数、双修饰键实际投出 flags 序列（按下累积掩码与 tap-down 精确断言，Control 在 Shift 仍按住时抬离、Shift 清零收尾——预建释放直接用计划内 ModsUp 规格，计数看不见的错误掩码由 TARGETED_POSTED_FLAGS 逐事件断言；tap-up 携带 HIDSystemState 源真实键盘状态属 CU-01 实测形状，不对其断言——运行测试者按住的真实修饰键无法与派发残留区分）、取消 / 死进程 / 绑定复核失败中止的 Partial 与释放、创建失败注入（首步按下 / 预建释放失败零投递零释放返回明确错误、按下后后续创建失败仍投出预建释放、文本非首步失败保前缀 Partial），单一测试消除并行计数器竞态）。历史真实探针（2026-10-08）：AppKit 多 chunk 含代理对 insert_text 完整落地、return 与 shift+left 生效、最小化按闸拒绝；Browser insert_text 能力闸零事件拒绝；全程前台、焦点与剪贴板不变。

CU-08 增五项定向回归：契约层 `pointer_actions_validate_against_observed_bounds`（坐标越界 / NaN / inf → OutOfBounds、drag 双端点各自校验、滚动增量非有限 → Invalid、kind 映射 Pointer）、`window_moves_require_finite_origins`（负全局坐标合法、NaN / inf → Invalid）、`window_dispatch_mints_one_permit_per_consume`（伪造句柄 UnknownHandle、跨 scope CrossRun、取消先于台账、UserActive 不消耗、窗口绑定长活逐次独立 permit、Once 恰一次、消费后撤销阻断在途派发）；macos 层 `pointer_actions_reject_without_dispatching`（取消 → 台账复查 → 越界 → 死进程 → 身份错配逐层先于能力闸，AX 动作缝与遍历缝计数钉零）与 `move_window_gates_precede_the_position_seam`（伪造凭证 / NaN 原点 / 死进程 / 身份错配 / 凭证二次使用 / 消费后撤销 / 取消分别先于 AXPosition 写缝拒绝，AX_ACTION_SYSTEM_CALLS 计数钉零，单一测试消除并行计数器竞态）。复审（2026-10-07 6.1 sol）后增两项：`move_minimized_gate_fails_closed_on_unknown_state`（AXMinimized 未知 → ProbeUnavailable 精确拒绝、Some 值原样传递、纯函数不触 AX 动作缝计数钉零）与 `retained_cf_value_releases_exactly_once_on_every_path`（AXValue create-rule：RetainedCfValue drop 恰一次释放——加一 retain 后计数 2→1，CFString 自释放平衡）；同批 move_window 的 AXValue 改 RetainedCfValue RAII 释放（budget.arm 失败路径不再泄漏），探针 axmove 还原改读回帧驱动（UnknownEffect 已移动同样还原、读回帧缺失记 unknown、rejected 已移动报 moved_while_rejected），origin_reached 补宽度核对。历史真实探针（2026-10-08）：AppKit axmove 派发且帧读回到位、最小化按闸拒绝，各族 click / drag / scroll 均按能力闸拒绝；窗口移动是否带动用户鼠标未证明，见 [ENV-08](../../plan/env-08-macos-real-system.md)。

CU-24 设计与拒绝边界（2026-10-10）：锁屏使用仍无生产路径，`Environment` 契约只表达 `isolated_desktop` 与 `native_background`；新增 `locked_use_environment_is_rejected_by_the_contract` 钉住两值序列化并证明 `locked_use` 观测 JSON 反序列化失败。设计要求宿主活跃 turn 签发单次短期解锁尝试，普通 Once / ForRun 批准不解锁；停用先撤销尝试并恢复锁定，卸载失败保持拒绝态。特权组件、系统安装与授权、真实锁屏序列均未实施 / 未验收，不以普通 AX 后台能力替代；实施前须用户明确启用并裁决特权方案（2026-10-13 仍未触发）。

CU-22 Windows 边界（2026-10-13 复核）：没有 Windows 后端。`HostSurface::local()` 在 macOS 装箱 `MacosNative`，其它平台（含 Windows、Linux）装箱 `UnsupportedProbe`，回归 `unsupported_probe_fails_closed` 只钉这条拒绝边界；`NativeHost::isolated()` 是 CU-21 的 Linux guest，不代表 Windows 支持。UIA、捕获、定向输入与 UIPI / 会话拒绝须在独立 Windows 会话或 VM 上实现并验收，见 [CU-22](../../plan/cu-22-windows-isolation.md)。

CU-25 设计边界（2026-10-10）：目标音频仍无生产入口，动作、观察、环境契约与 macOS 权限预检均不含音频。原测试内的音频拒绝模拟（`audio_capture_is_rejected_by_the_contract`）只在测试里运行、不对应任何生产代码，已按 2026-10-13 用户裁决删除（B22）；拒绝规则仍以 [CU-25 设计](../../plan/cu-25-audio.md) 为准，真正接入音频时要和生产入口同批重写回归。真实采集、OS 音频授权、在途释放与 Provider 音频输入待环境，保存录音不等于模型收到音频；实施前须用户显式开启音频场景（2026-10-13 仍未触发）。
