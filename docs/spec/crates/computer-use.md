# pawork-computer-use

> 独立 computer use 库，2026-09-17 按用户授权新增，并按“不干扰本机键鼠”的要求改为隔离桌面。生产经 tools → Host；不改 GUI wire 或 domain 事件。

## 1. 职责与边界

纯 Rust 通过 RFB 3.8 操作专用容器内的 Xvnc 虚拟桌面。所有截图和输入都在独立显示器，不接触本机 HID、屏幕、焦点或剪贴板；不存在 macOS 回退实现。应用须运行于该环境，不能直接控制宿主已有应用。无 Pawork 内部依赖、GPUI、Provider、shell、自有 JS Runtime 或模型指定的路径/网络端点。容器需显式启动，库不管理 Docker 进程。

CU-02 起新增 `target` 模块：本机后台目标、观测与动作能力的有类型契约（纯数据类型与校验逻辑，不触平台 API、不触网）。本机探针与动作派发属下游任务（CU-03+），尚未接入生产路径与 tools；GUI 不直接访问。

CU-16 起新增 `approval` 模块：应用与网站范围的 Host 审批契约。授权把 `TargetIdentity`（整应用或浏览器内单源网站）绑定 workspace/run `Scope`，由宿主在显式用户审批后签发 once / for-run 授权；`TargetRegistry` 在绑定、观测、校验与派发路径上先查台账授权，未授权、已撤销、跨目标与受保护目标先于任何 probe 调用拒绝；网站目标另经 `NativeProbe::current_origin` 接缝复核窗口当前页面身份（含宿主捕获前预检 `require_authorized`），同窗口跨源导航即拒。Pawork 自身 UI 与 OS 权限界面内置为受保护目标。OS 权限（Screen Recording / Accessibility / Automation）与 Pawork 目标授权分离：契约不授予、不变更系统权限，缺失由 CU-03+ 探针如实报告。


CU-03 起新增 `macos` 模块（仅 macOS）：`NativeProbe` 的真实后端与应用发现、窗口选择与受控启动。发现只读窗口服务器元数据（bundle id + 族、进程实例、窗口计数），不读标题、不读 AX 树；标题与 AX 读取是目标内容访问，`list_windows` 先核验目标与 scope 授权再读，标题只在该调用显式要求时复制出窗口服务器。窗口存活用应用自身 AXWindows 交叉验证（已关闭窗口在窗口服务器列表长期残留为幽灵）：私有但长期稳定的 `_AXUIElementGetWindow` 可用时按窗口服务器 id 精确对应（幽灵 id 永不映射，同帧关窗只失效自己），符号缺失时退化为帧组闭合（同帧窗口服务器计数 = AX 计数才判活，歧义 fail-closed 且可能连带失效同帧幸存窗）。启动只接受 LaunchServices 可解析的 bundle 身份（模型不能传可执行路径），授权检查先于一切系统调用，启动不激活、不夺焦点。Accessibility 缺失按 `PermissionMissing`、其余 AX 失败按 `ProbeUnavailable` 如实拒绝；网页 origin 仍无信号源、按契约 fail-closed（AX 树版本信号源由 CU-05 落地）。尚未接入 tools / Host 生产路径。

CU-04 起 `macos` 模块新增窗口级截图：`capture_window` 按 CU-01 实测的 ScreenCaptureKit 单帧窗口捕获路线实现（桌面无关过滤器，遮挡 / 后台 / 最小化窗口仍返回自身内容，不激活目标、不动前台与焦点）。门槛顺序：台账授权 → 进程实例 → 身份绑定（实例 pid 的 bundle id 系统回读须等于获授权身份，与 `list_windows` 共用同一核验，错配按 Invalid 先于任何 AX 读取拒绝）→ 窗口存活 + 代际（复用 CU-03 同一快照证明）→ OS Screen Recording preflight（权限拒绝先于捕获缝，永不发起 TCC 请求）；SCWindow 按窗口 id + 属主 pid 双因子定位，输出经 `scalesToFit` 铺满配置帧（内容恒覆盖全图，整图坐标换算才成立），捕获与存活证明之间关窗按 WindowReplaced、其余捕获失败保留 OS 原因按 ProbeUnavailable 如实拒绝，无旧图 / 残帧路径。上限沿用现有口径：原始像素单边 ≤4096、总像素 ≤8M、捕获比例 ≤2x，输出基线 JPEG 最长边 ≤1280、字节 ≤512KiB（质量阶梯 75/50/30），completion handler 10 秒超时；产物继续走现有 ContentPart::Image 与持久消息通路。契约层相应新增 `NativeProbe::window_size` 接缝：观测记录窗口尺寸，缩放后旧观测在注册 / 消费 / 元素派发三路按 StaleHandle 拒绝（恢复尺寸后在途租约可放行），尺寸不可得按 WindowReplaced fail-closed。仍未接入 tools / Host 生产路径（CU-10 / CU-17）。

CU-05 起新增有界无障碍树与元素定位。契约层（target.rs）提供 `AxTreeBounds`（深度 24 / 节点 4096 / 单串 200 字符 / 整读 10 秒，固定常量不可按调用调）、`AxTreeRead`（前序节点流，nodes[0] 恒为窗口根）、`ax_tree_revision` 版本指纹（窗口本地坐标，纯移动不推进版本）、`ElementQuery` / `ElementLookup` / `lookup_element`（角色 + 名称查找，歧义不取第一，截断树下唯一匹配不可证不签发）。macOS 后端落地 `MacosNative::read_ax_tree` 与真实 `tree_revision`：门序为台账授权 → 进程实例 → 身份绑定 → Accessibility preflight → 窗口存活 + 代际 → 有界遍历；读使能对 Chromium 族先设 `AXManualAccessibility`（VoiceOver 同款，幂等不改 UI，渲染进程异步物化树、首读可能如实只含窗口铬）。时间预算同一 deadline 贯穿窗口解析 / 读使能 / 遍历，每次 AX 调用以该次调用开始时的剩余预算为逐元素 messaging timeout、返回后复核时钟、交付前最终复核，符号缺失或设置失败拒读。敏感边界：永不读 AXValue；安全输入框按 subrole 识别（AXTextField + AXSecureTextField，识别失败保守按敏感）连名都不读；名称读取失败置 names 标志使名称查询不可证（角色单条件查询不受影响）；子列表与上报计数不一致直接拒读。读失败是错误，成功读的根无子是「应用未暴露元素」的肯定答案，空树不伪装。仍未接入 tools / Host 生产路径（CU-10 / CU-17）。

## 3. 对外 API 面

`Computer::isolated()` 惰性连接专用桌面；`new(Arc<dyn Backend>)` 供宿主自定义（其隔离由宿主保证）。`execute(scope, action, cancelled)` 为同步调用。`status` 返回连接的 capture/input 可用性；`screenshot` 返回 Observation（id、连接 session_id、虚拟宽高、图像宽高）和 JPEG。输入动作携带 observation_id：click、move、drag、scroll、type_text、key。受限键名与 command/shift/control/option；Linux 快捷键用 control，command=Super，option=Alt。scroll 正值右/下，每 40 像素换算一步滚轮。

`target` 模块对外面（契约，尚无生产调用方）：`TargetRegistry::bind_window / begin_observation / issue_element / validate_window / consume_observation / consume_element`；句柄 `WindowHandle / ObservationHandle / ElementHandle` 为 serde 透明字符串（`{w,o,e}-<pid>-<宿主启动纳秒>-<进程级序号>`，命名空间保证 Host 重启且 PID 复用时新值永不撞旧值），模型只能回传宿主签发值，不能提交裸 PID、绝对路径或网络端点；`TargetObservation` 携带 Environment（`native_background` / `isolated_desktop`）、窗口句柄、图像像素与窗口点双尺寸（CU-04 起窗口点尺寸为捕获时记录值，`NativeProbe` 增 `window_size` 接缝供注册 / 消费 / 元素派发三路复核，缩放即旧观测 StaleHandle）；`image_to_window` 把模型图像像素换算为窗口坐标；`NativeActionKind` 十动作词汇（窗口截图、AX 读、AX 语义写、AX 按压、定向文本/键、菜单快捷键、菜单栏按压、指针、窗口移动、窗口缩放）配 `background_capability`（CU-01 实测矩阵，按应用族 × 动作 × 最小化态返回 Supported / Unsupported / Unverified）与 `require_background` 闸；`TargetError` 十三变体覆盖全部拒绝语义（CU-16 增 `NotAuthorized` / `ForbiddenTarget` / `SiteChanged`）。CU-05 起增有界树面：`AX_TREE_BOUNDS`（深度 24 / 节点 4096 / 单串 200 字符 / 整读 10 秒，固定常量——初读与消费复核共用同一边界，宿主不可调，`AxTreeBounds::validate` 复核硬上限）、`AxTreeNode`（子索引 path / 深度 / 角色 / 名称 + 截断标志 + 名称不可读标志 / enabled / focused / 窗口本地帧 / 动作表 / 子数 / 深度截断）、`AxTreeTruncation`（深度 / 节点 / 文本 / 名称不可读四面标志）、`AxTreeRead`（前序节点流 + 版本指纹 + 截断，nodes[0] 恒为窗口根）、`ax_tree_revision`（FNV-1a 64 位指纹：同树同边界同版本，发射差异改变输入流；非加密散列、理论碰撞存在，是廉价变更信号而非防篡改证明；帧为窗口本地坐标，纯移动不推进版本）、`ElementQuery::new`（角色精确 + 名称大小写不敏感子串，至少一项否则 Invalid）、`ElementLookup`（Unique 可签发 / NoMatch 带 tree_truncated / Ambiguous 带匹配数 / UnprovenUnique——深度 / 节点截断下唯一匹配不可证、不签发；文本截断与名称不可读只使含名称条件的查询不可证，角色单条件查询在结构完整读上仍可签发）与 `lookup_element`。

`approval` 模块对外面（CU-16，契约，尚无生产调用方）：`TargetIdentity`（serde `tag="kind"` snake_case）两变体——`application`（整应用，bundle id + 族）与 `website`（浏览器内单源网站；构造要求 browser 族，origin 归一化为小写 `http(s)://host[:port]`，host 限域名字符且含字母数字，端口限 1..=65535 并规范化前导零，拒路径 / 查询 / 片段 / userinfo / 空 host / 非法端口，IPv6 字面量暂按 fail-closed 拒绝）；`TargetIdentity::validate` 在授权入口（`grant / check / spend` 与 `bind_window`）统一复核，公开枚举字段与派生反序列化不能绕过构造校验。`GrantKind::{Once, ForRun}` 对应宿主 `ApprovedOnce` / `ApprovedForRun` 决定；`TargetAuthorizer::new(protected_bundle_ids)` 在永远内置的 `MINIMUM_PROTECTED_BUNDLES`（Pawork 自身 UI `dev.pawork.desktop` 与 macOS 权限界面 systempreferences / securityagent / usernotificationcenter / coreservicesuiagent，大小写不敏感、宿主只能加不能减）之上追加宿主保护集，`grant / revoke / revoke_scope / check / spend`。`TargetRegistry` 相应增 `with_authorizer / authorizer / grant / revoke / revoke_scope / require_authorized`（宿主预检闸：连接、启动、捕获、读树前调用，非消耗；先查台账，网站目标再复核窗口当前 origin，跨源 / 不可得即 SiteChanged）；`bind_window` 收 `TargetIdentity`；`ValidatedWindow.app` 更名 `target: TargetIdentity`；`NativeProbe` 增 `current_origin` 页面身份接缝；`TargetError` 十三变体（CU-16 增 `NotAuthorized` / `ForbiddenTarget` / `SiteChanged`）。


`macos` 模块对外面（CU-03，macOS-only，尚无生产调用方）：`MacosNative`（`Clone` 共享窗口代际账本；一把互斥锁串行化枚举、账本同步与代际提取，绑定与校验必须走同一实例的克隆——独立创建的实例各自编号）实现 `NativeProbe` 五接缝：`process_instance_alive`（NSRunningApplication 终止态 + sysctl 启动令牌双判）、`window_generation`（同一次快照内的窗口身份核验 + 代际提取）、`window_size`（CU-04，与 `window_generation` 同一快照纪律读窗口服务器实时点尺寸，证明失败 None）、`tree_revision`（CU-05 起真实实现：属主 pid 定位 → 窗口元素解析 → 同边界重走 → 指纹，任何失败 None fail-closed）与 `current_origin`（无信号源恒返回 None，网站目标随之 fail-closed）。另加发现与启动面：`permissions()` 返回 Screen Recording / Accessibility 当前态（只读 preflight，永不触发 TCC 弹窗）；`list_applications()` 列 Regular 激活策略应用（身份 + 进程实例 + 显示名 + 窗口服务器 layer-0 计数，可能含幽灵；不读标题、不读 AX 树，只读、不激活）；`list_windows(authorizer, scope, identity, instance, include_titles)` 授权核验先于一切 AX / 标题读取，且进程实例必须确实属于获授权身份（pid 的 bundle id 经 NSRunningApplication 回读比对，错配按 Invalid 拒绝——一个应用的授权解不开另一个进程），返回 layer-0 标准窗口（窗口 id + 同快照代际 + 全局点坐标帧；标题仅 include_titles 且具 Screen Recording 权限时、且仅对目标自身窗口复制出窗口服务器，其它应用的标题不进内存）；`resolve_identity(bundle_id)` 不启动解析已安装应用身份（族分类随附）；`launch_authorized(authorizer, scope, identity)` 授权检查先于一切系统调用，LaunchServices 不激活启动并返回新进程实例。CU-04 起增 `capture_window(authorizer, validated)`：台账授权 → 进程实例 → 身份绑定 → 窗口存活 + 代际 → Screen Recording preflight 五门序全部通过才触捕获缝，返回 `WindowCapture`（窗口身份 + 代际、图像像素宽 / 高、窗口点宽 / 高、基线 JPEG）。 CU-05 起增 `read_ax_tree(authorizer, validated)`：台账授权 → 进程实例 → 身份绑定 → Accessibility preflight → 窗口存活 + 代际 → 有界遍历缝，返回 `AxTreeRead`；同一 deadline（AX_TREE_BOUNDS.max_read）贯穿窗口解析、读使能与遍历，每次 AX 调用以该次调用开始时的剩余预算为逐元素 messaging timeout、返回后复核时钟，交付前最终复核，符号缺失或超时设置失败拒读；遍历前在应用元素设 `AXManualAccessibility`（Chromium 族读使能，幂等、不改 UI、该属性不支持时如实按当前暴露读），永不读 AXValue，安全输入框按 subrole 识别不读名；子列表与上报计数不一致拒读，名称读取失败置 names 标志。`LaunchError` 区分授权拒绝（`Denied(TargetError)`，先于系统调用，回归以启动缝调用计数钉零）与启动失败（`NotFound` bundle id 不可解析 / `Failed` / `ExitedEarly` 启动后读不到实例令牌）；`TargetError` 增两变体至十五：AX 不可得且权限缺失按 `PermissionMissing("accessibility")`，权限在而 AX 调用失败（应用无响应 / 属性不支持 / 符号缺失）按 `ProbeUnavailable(原因)`，两者都拒绝访问。
## 4. 关键行为与语义

坐标从 JPEG 左上角开始，严格在 `[0,width) × [0,height)`，按虚拟尺寸缩放。截图最长 1280、≤512 KiB；raw framebuffer 单边 ≤4096、总像素 ≤8M，响应字节、矩形、消息与 8 秒 I/O 均有上限。每次全量截图覆盖全部像素后才返回，禁止残帧伪装截图。观察绑定 scope、连接身份和尺寸，60 秒失效；输入前即消费，错误不允许重用。断线后新连接身份使旧观察失效；不自动重试输入。取消/错误时尝试释放，传输失败断开由 Xvnc 释放客户端状态。成功仅代表投递，实际效果需截图复验。

target 契约沿用并细化同一租约模型：观测与元素句柄 60 秒 TTL、一次性消费——消费元素同时作废父观测与兄弟元素句柄；校验通过即消费，后续派发失败不回收。每次使用按固定顺序校验：取消 → 存在性（伪造/未知 → UnknownHandle，宿主重启后全部旧句柄落入此类）→ Scope（跨 Run / 跨 workspace → CrossRun）→ 过期或已消费 → StaleHandle → 进程实例（退出或重启 → ProcessRestarted）→ 窗口代际（销毁或标识符复用 → WindowReplaced）→ AX 树版本（树前进 → TreeChanged，AX 观测消费与元素句柄同校）；坐标非有限值或越出图像边界（含边缘本身）→ OutOfBounds。元素句柄只能由 AxTree 观测签发。后台能力以 CU-01 实测为唯一依据：仅 Supported 放行，Unsupported 与 Unverified 同拒（BackgroundUnsupported）且永不回退全局输入；指针动作三类应用族后台一律拒绝；AppKit 定向键在窗口最小化时拒绝；AppKit AXPress 与最小化态窗口移动/缩放未单独实测，按 Unverified 拒绝。用户接管同一目标没有系统级仲裁（CU-01 T6b），取消是唯一停止机制。

CU-16 起校验链在 StaleHandle 之后、进程实例 probe 之前插入授权裁决：绑定、观测签发、窗口校验与动作消费均先查 `(Scope, TargetIdentity)` 授权（无授权 / 已撤销 / 跨目标 → NotAuthorized，受保护 bundle → ForbiddenTarget），台账拒绝零 probe 调用（回归以计数钉住）；宿主捕获前预检 `require_authorized` 同序执行——先查台账、再复核网站目标当前 origin，跨源或 origin 不可得即 SiteChanged，拒绝时宿主不得连接 / 捕获 / 读取目标；真实平台后端的捕获 / 输入访问以该预检接线为前提，随 CU-03+ 落地后验证。once 授权只在其余校验全部通过后、动作真正放行时才消耗——绑定需要有效授权但不消耗，陈旧目标或拒绝路径不烧掉用户的单次批准；一次观测或一次输入各为一个动作。元素句柄签发不重复查授权（其父观测已带授权），撤销在观测与派发之间到达时由 `consume_observation` / `consume_element` 的先于 probe 复查阻断。授权只覆盖被批准目标：整应用授权不覆盖其内任何网站，单源网站授权不覆盖浏览器与其它源；网站目标在绑定与每次 live 校验时经 `NativeProbe::current_origin` 复核窗口当前 origin（归一化比较，尾斜杠 / 大小写 / 端口拼写不能绕行），同窗口跨源导航或 origin 不可得一律 SiteChanged，先于派发拒绝。身份在授权入口统一 `validate` 复核，公开枚举与反序列化不能绕过构造校验。授权仅存内存，随 run 结束（`revoke_scope`）或 Host 退出消亡；已执行动作是历史，撤销不回写。


CU-03 macOS 后端把契约接缝落成真实平台信号。进程实例 = pid + `kern.proc.pid` sysctl 启动时间（微秒；只读 kinfo_proc 头部 16 字节的 start timeval，不依赖内核版本相关的完整结构布局）+ NSRunningApplication `isTerminated` 终止态：PID 复用或进程退出后旧实例永不判活。窗口代际账本随窗口服务器快照同步：新见到的窗口 id 分配新代际，快照中消失的 id 被遗忘，id 复用时拿到新代际；枚举、账本同步与代际提取在同一把互斥锁内完成，旧快照永远覆盖不了新账本，每个给出的代际都来自它被核验的那次快照（绑定与校验共用同一 `MacosNative` 实例的克隆）。窗口存活是双条件：CGWindowList 在册 **且** 应用自身 AXWindows 证明其存在——macOS 已关闭窗口会在窗口服务器列表长期残留（幽灵项，属性与活窗一致，TextEdit / Terminal 实测），单凭在册不能证明存活。对应关系两级：`_AXUIElementGetWindow`（HIServices 私有导出，yabai / Hammerspoon 等同族依赖）可用时把 AX 窗口映射到窗口服务器 id，幽灵 id 永不映射——同帧关窗只失效自己，幸存同帧窗继续有效（定向回归与真实验收双重钉住）；该导出缺失或失败时退化为帧组闭合——同帧窗口服务器计数等于 AX 计数才判活，幽灵只 inflate 服务器侧，任何一侧多余即歧义 fail-closed，且组内任一 AX 窗口若同时匹配组外 CG 窗口（epsilon 匹配不可传递，一个 AX 候选可落进两个帧组）同样歧义拒绝——重叠下同帧幽灵会连带失效幸存窗直到幽灵被回收，文档化且仍然安全。读取授权另受身份-进程绑定约束：list_windows 在 AX / 标题访问前经 NSRunningApplication 回读 pid 的 bundle id 比对获授权身份，错配按 Invalid 拒绝。Accessibility 权限缺失时授权窗口路径按 `PermissionMissing("accessibility")` 拒绝；权限在而 AX 调用失败按 `ProbeUnavailable` 拒绝（错误码保留在消息里，kAXErrorAPIDisabled=-25211 仍归权限类，CannotComplete=-25204 等其余码归 probe 失败；HIServices 符号缺失的预检失败同样归 ProbeUnavailable 而非误报缺权限）；`window_generation` 对任何失败一律 None（fail-closed）。受控启动恒用 `NSWorkspaceLaunchWithoutActivation`（0x200），不激活、不夺焦点；授权检查先于 LaunchServices（回归以启动缝调用计数钉零），bundle id 解析不出已安装应用按 NotFound 拒绝，启动后读不到实例令牌按 ExitedEarly 拒绝。族分类是启发式：声明 http/https URL scheme → Browser（Chromium / WebKit / Gecko 内核均覆盖），捆绑 Electron / Chromium Embedded Framework → Chromium，其余 → AppKit，只喂 CU-01 能力矩阵。系统权限只读预检（ScreenCapture preflight + AXIsProcessTrusted），任何路径都不发起 TCC 请求。链接细节：AppKit 经空 extern 块强制链接以加载 NSWorkspace / NSRunningApplication 类，HIServices 沿用 CU-01 的 dlopen 模式。

CU-04 窗口截图沿用同一诚实性纪律。捕获门序固定为台账授权 → 进程实例 → 身份绑定（bundle id 系统回读，错配按 Invalid 先于 AX 读取拒绝）→ 窗口存活 + 代际（复用 CU-03 同一快照证明）→ Screen Recording preflight → SCK 捕获缝，任一前置失败时捕获缝零调用；Screen Recording 缺失按 `PermissionMissing("screen recording")` 在捕获前拒绝，任何路径不发起 TCC 请求。SCWindow 按窗口 id + 属主 pid 双因子定位；捕获与存活证明之间关窗按 WindowReplaced，其余捕获失败保留 OS 原因按 ProbeUnavailable；每次捕获都是全新单帧且 `scalesToFit` 铺满配置帧（内容恒覆盖全图），completion handler 10 秒超时，无旧图 / 残帧 / 部分数据路径。completion 状态机是显式所有权：超时先标记 abandoned，迟到回调由 handler 侧立即释放已 retain 对象，结果恰在超时与加锁之间落盘时由等待方释放，结果与错误同时到达时由 deliver 统一释放——错误交付永不携带已 retain 指针，filter / config 在超时、错误、nil 全路径释放——任何路径都不泄漏对象或迟到帧。图像管线三级收口：`capture_scale` 在 ≤2x 内再受单边 ≤4096、总像素 ≤8M 约束（不满足即拒绝，不降级放大），`capture_pixel_size` 逐轴 floor 并复核整数乘积（独立四舍五入可突破预算），`checked_frame_layout` 在复制实际像素前对交付帧复核同一预算；BGRA→RGB 逐行 stride 校验，截断 / 不一致拒绝；基线 JPEG 最长边 ≤1280、字节 ≤512KiB（质量阶梯 75/50/30，与隔离桌面同口径）。观测记录捕获时窗口点尺寸，`begin_observation` / `consume_observation` / `consume_element` 在树版本校验后与 `window_size` 实时值比对（±0.5pt，同后端帧容差）：缩放即 StaleHandle（重新观测恢复，窗口绑定不受累），恢复尺寸后在途租约可放行，尺寸不可得按 WindowReplaced fail-closed；坐标映射不变——`image_to_window` 把模型图像像素换算为窗口点（真实验收：833×529 窗口的图像中心点精确映射 (416.5, 264.5)）。截图不激活目标、不动前台与焦点（front_unchanged 真实验收钉住）。

CU-05 有界树读取沿用同一诚实性纪律。读树门序固定为台账授权 → 进程实例 → 身份绑定 → Accessibility preflight → 窗口存活 + 代际 → 遍历缝，任一前置失败时遍历缝零调用（回归以计数钉住）；Accessibility 缺失按 PermissionMissing 在内容读之前拒绝，AX 调用失败保留原因按 ProbeUnavailable，两者都拒绝访问。遍历有界：深度、节点、文本截断是确定性的、在读取上置标志；时间预算（10 秒）是同一 deadline 贯穿窗口解析、读使能与遍历，每次 AX 调用以该次调用开始时的剩余预算为逐元素 messaging timeout、返回后复核时钟、交付前最终复核，超支整读失败——超时部分树既不能支撑稳定版本也不能支撑可证查找。结构一致性：已上报正子数的元素，其子列表缺席 / 失败 / 数量不足 / 含空指针一律拒读。名称读取失败（真实应用存在，TextEdit 文本区 AXDescription 返回 kAXErrorFailure）不伪装不匹配：置节点 name_unreadable 与读级 names 标志。读失败是 TargetError，成功读 nodes[0] 恒为窗口根：根无子是「应用未暴露元素」的肯定答案，空树永不伪装读失败。树版本是一次有界读的 64 位 FNV-1a 指纹（同树同边界同版本；帧为窗口本地坐标，纯移动不推进版本，缩放 / 布局变化推进），消费元素句柄或 AxTree 观测时后端以同一边界重走复核；指纹是非加密散列——理论碰撞存在，作为廉价变更信号而非防篡改证明。元素查找永不歧义取第一：多匹配按 Ambiguous（带已读部分匹配数）；唯一匹配的可证性精确到判据——深度 / 节点截断使一切查询不可证（UnprovenUnique 不签发），文本截断与名称不可读只使含名称条件的查询不可证，角色单条件查询在结构完整读上仍可签发；零匹配带 tree_truncated 区分「完整树上不存在」与「未读部分未知」。敏感边界：元素内容（AXValue）永不读取；安全输入框按 subrole 识别（AXTextField + AXSecureTextField；识别失败保守按敏感），连名称都不读，读树顺势获取密码 / Token / 文档正文的路径不存在。Chromium 族读使能：每次读树前在应用元素 best-effort 设 AXManualAccessibility（VoiceOver 同款，幂等、不改 UI）；渲染进程异步物化树（真实验收实测约 1–2 分钟），全新 Chromium 窗口首读可能如实只含窗口铬，后续读收敛到完整树——「此刻只暴露这些」是肯定答案而非错误。
## 5. 依赖与 feature


serde / thiserror / image（仅 JPEG，已有 workspace lock 版本）；网络为 std::net。无 `pawork-*` 依赖。独立 Cargo 元数据不继承 workspace；`publish=false`，License 待定。隔离桌面运行依赖 Docker / Xvnc，不改变 CLI / Desktop 的纯 Rust 构建链。CU-03 起 macOS 原生后端是库本体的一部分：objc / core-foundation / core-graphics（elcapitan feature）/ libc 为 `[target.'cfg(target_os = "macos")'.dependencies]` target-gated 正式依赖（均复用 workspace 已锁定版本），仅 macOS 目标编译，非 macOS 目标仍无任何平台框架；cocoa 留 target-gated dev-dependencies，仅供 CU-01 / CU-03 人工探针 examples（非产品路径）；CU-04 起 `block` 由 dev 提为 target-gated 正式依赖（ScreenCaptureKit completion handler 回调所需，复用 workspace 已锁定版本）。crate 级 `[lints.rust] unexpected_cfgs` 保持 warn：check-cfg 把 objc 0.2 宏展开引用的 `cargo-clippy` cfg 声明为已知值使其不再触发，其余未知 cfg 照常告警。
## 6. 红线与不变量

Pawork 集成通过 [tools](tools.md) 复用 ExternalPlugin / requires_approval / untrusted 与 ReadOnly 拒绝；构造不触网，审批在连接前。固定 loopback 端口、RFB 3.8、桌面名匹配只是配置检查，不是远程身份认证或隔离证明；部署必须使用所附虚拟桌面，不转发物理屏幕。容器不挂载宿主目录/设备/桌面/剪贴板，只发布 loopback 端口，拒绝第二个 viewer。服务器 None 认证仅限这个本地部署。环境缺失/断线直接失败，没有回退本机路径。截图为未信任数据，仍持久化并发送给模型，不提供通用视觉脱敏。应用焦点变化仍需新截图验证；隔离解决本机输入争抢，不保证容器完全不消耗宿主资源。

target 契约层不变量：契约代码不调用任何平台 API（活跃状态经 `NativeProbe` 宿主注入）；句柄只能由 `TargetRegistry` 签发，模型输入永远按未知句柄拒绝兜底；无后台实测支持的动作直接拒绝，不存在全局输入、前台激活或事后恢复状态的隐式降级。

审批契约层不变量（CU-16）：授权只能由宿主在显式用户审批后签发——模型侧只能触发检查，永不能签发或扩大授权；自动审批 resolver 不能满足 Policy AskUser，因此永远产生不了授权，不另造审批框架。台账授权拒绝（NotAuthorized、ForbiddenTarget）先于一切 probe 调用（回归以 probe 调用计数钉住）；SiteChanged 裁决须经 `current_origin` 接缝（不触碰进程实例与捕获后端）；生产捕获与 Policy 接线待 CU-03+ 验证。`MINIMUM_PROTECTED_BUNDLES` 内置 Pawork 自身 UI 与 macOS 权限界面（大小写不敏感、宿主只能加不能减、默认构造即生效）：受保护目标永不可授权、永不可绑定，Agent 无法经 Pawork 审批界面或系统权限界面自我批准；契约不存在任何变更 OS Screen Recording / Accessibility / Automation 权限的 API，系统权限缺失只能如实报告。网站目标 origin 不可得即 fail-closed（SiteChanged）。逐目标持久授权不存在：持久允许仅走已裁决的 ApprovalMode / workspace trust 设置口径，新增逐目标持久授权须先过 ADR。


macOS 后端不变量（CU-03）：启动只接受 LaunchServices 可解析的 bundle 身份，不存在任何可执行路径入参；授权裁决先于一切系统调用——未授权、已撤销、跨目标与受保护目标在触碰 LaunchServices 之前即拒绝（回归以启动缝调用计数钉零）。启动恒不激活、不夺焦点（`NSWorkspaceLaunchWithoutActivation`）；发现与列举全程只读。读取授权闸：`list_windows` 先核验 (scope, 目标) 授权再碰 AX 树与标题，未授权读取连一次 AX 调用都不发生；授权身份与进程绑定——AX / 标题访问前回读 pid 的 bundle id 比对获授权身份，错配按 Invalid 拒绝；标题按 owner pid 门控，只复制获授权目标自身窗口的标题，其它应用的标题从不进内存；发现路径（`list_applications`）不读标题、不读 AX 树，窗口计数是窗口服务器元数据（可能含幽灵）。窗口标题是内容，仅在授权调用显式 `include_titles` 时才从窗口服务器字典复制出来（没有 Screen Recording 权限时系统本就不给标题）。`permissions()` 只读 preflight，任何路径都不触发 TCC 弹窗、不变更系统权限。窗口存活以「窗口服务器在册 + 应用自身 AXWindows 证明」双条件判定：`_AXUIElementGetWindow` 可用时按窗口服务器 id 精确对应，缺失时帧组闭合（计数相等且组内 AX 候选不跨组重叠，否则拒绝）、歧义 fail-closed；AX 不可得一律 fail-closed，绝不凭 CGWindowList 在册单独认定存活（已关闭窗口在那里长期残留为幽灵）。`tree_revision` / `current_origin` current_origin 没有信号源就报不可得，网站目标随之 fail-closed，不静默信任无法复核的状态；tree_revision 自 CU-05 起有真实信号源（同边界重走指纹，任何失败 None fail-closed）。窗口代际的枚举、账本同步与提取在同一把锁内完成，旧快照永远覆盖不了新账本；账本只由同一 `MacosNative` 实例的克隆共享。

CU-04 截图不变量：捕获门序（台账授权 → 进程实例 → 身份绑定 → 存活 + 代际 → Screen Recording preflight）任一拒绝先于捕获缝生效（回归以捕获缝调用计数钉零），权限缺失永不在捕获后才报告；获授权身份与实例进程错配在任何 AX 读取前按 Invalid 拒绝——一个应用的授权永解不开另一个进程的窗口。不存在旧图 / 残帧 / 部分像素返回路径，失败必带真实终态（WindowReplaced / ProbeUnavailable / PermissionMissing）；窗口内容恒铺满输出帧，不存在黑边伪装截图。completion 超时、迟到回调与「错误伴随结果」全路径释放已 retain 对象（错误交付永不携带所有权），filter / config 在超时、错误、nil 全路径释放，无泄漏路径；整数输出尺寸逐轴 floor 并复核乘积，交付帧在复制像素前复核预算，取整永不突破上限。窗口缩放即观测失效，契约不存在跨尺寸坐标复用；截图永不激活目标、永不改变前台与焦点，永不发起 TCC 权限请求。

CU-05 有界树不变量：读树门序（台账授权 → 进程实例 → 身份绑定 → Accessibility preflight → 存活 + 代际 → 遍历缝）任一拒绝先于遍历缝生效（回归以计数钉零），未授权读树连一次 AX 内容调用都不发生。元素内容（AXValue）永不读取；安全输入框按 subrole 识别（AXTextField + AXSecureTextField），识别失败保守按敏感不读名——读树路径不存在获取密码、Token 或文档正文的可能。树读取恒有界（深度 / 节点 / 文本 / 时间），时间预算是贯穿窗口解析、读使能与遍历的同一 deadline，每次 AX 调用以该次调用开始时的剩余预算为逐元素 messaging timeout 并复核返回时钟、交付前最终复核，符号缺失或超时设置失败拒读，超支整读失败而非返回部分树；结构不一致（子列表与上报计数不符、含空子元素）拒读；名称读取失败不伪装不匹配——置 names 标志使名称查询显式不可证；读失败是错误，成功读 nodes[0] 恒为窗口根，空树不伪装读失败、「应用未暴露元素」只能是肯定答案。树版本是有界读的 64 位 FNV-1a 指纹（廉价变更信号，非防篡改证明），消费时以同一边界重走复核，边界固定不可按调用调。元素查找永不歧义取第一：深度 / 节点截断下唯一匹配按 UnprovenUnique 不签发句柄，名称判据在文本截断或名称不可读下同规，角色单条件查询在结构完整读上仍可签发；NoMatch 以 tree_truncated 区分「完整树上不存在」与「未读部分未知」。Chromium 族读使能（AXManualAccessibility）幂等、不改 UI、失败不拒读；节点序号（path）只是单次读取内的解析线索，不是跨观测稳定身份。
