# CU-25 · 显式授权的目标音频采集

> 状态：设计完成，本地可做部分已尽；生产采集与模型音频输入未实现。阻塞：用户尚未显式开启音频场景（触发条件未满足），OS 音频授权与真实采集需真实桌面环境。更新：2026-10-13。

[返回 ROADMAP](../ROADMAP.md#未完成任务)

## 触发条件

用户选择音频使用场景并显式开启后开展，不默认采集。2026-10-10 用户限定只推进设计与可模拟拒绝边界，该触发尚未满足。

## 目标

补齐目标音频录制或模型使用链路，并明确二者的能力边界。

## 当前依据与读取范围

LCU 音频是原 runtime 的可选录制 API；保存录音不等于把音频送入模型。Pawork 当前没有 computer-use 音频链路。

[computer-use Spec](../spec/crates/computer-use.md)、[providers Spec](../spec/crates/providers.md)、[models Spec](../spec/crates/models.md)、[安全规格](../spec/security.md)、[LCU 音频说明](https://github.com/amontlabs/lcu/blob/21c4b5e70e9dedbc772f969cfdfbcc7ccc08139a/README.md)。

## 实施范围

- 先确认录制给用户还是作为模型输入、目标范围、格式 / 时长 / 字节预算及权限；不顺势录制其它用户应用的系统音频。
- 以 Rust 系统采集 API 实现实际支持的目标范围；若无法隔离范围，明确不支持而非默认录全桌面。
- 停止、取消、撤销和任务结束释放采集。若交给模型，先验证模型 / Provider 音频能力与完整编码通路。
- 需要演进媒体、持久化或 wire 时先做对应裁决和 golden；不把仅有文件保存记为模型听到音频。

## 完成条件与验证

- 真实音频来源、权限、预算和停止行为可核对，用户正常操作不受影响。
- 录制产物与模型实际收到的内容分开验收；未支持模型输入时保持明确限制。
- 未启用时零采集，取消或撤销后不继续录制，不含未授权应用内容。

## 设计结论（2026-10-10，独立 review PASS）

- 默认关闭；Once / ForRun 目标授权不能顺便开启音频。
- 桌面、系统混音、窗口、网站与未证实隔离的应用范围一律 Unsupported，不回退录全桌面；麦克风保持关闭。
- 关闭、停止、取消、撤销与任务终态先拒绝新请求；若流已启动，立即请求中止、拒收并丢弃迟到缓冲、释放系统资源与 Host 侧引用，结果未知时 fail-closed 如实报告。
- 用户侧录音与模型输入分开；保存文件不等于模型听到音频。

## 当前状态

生产路径没有目标音频入口：`Environment` 只有 `isolated_desktop` / `native_background`，十个 `NativeActionKind` 与两种 `ObservationKind` 均无音频，macOS 权限预检只有 Screen Recording / Accessibility，Host / Provider 也没有音频内容编码链。原测试内的音频拒绝模拟已按 2026-10-13 用户裁决删除（B22）；真正接入音频时与生产入口同批写回归。

## 本地可做范围与阻塞（2026-10-13 复核）

已尽的本地部分：

- 设计结论已独立 review PASS（见上节），能力边界、默认关闭、Unsupported 范围与释放顺序已定稿。
- 对照 HEAD 源码复核「无音频入口」事实：`crates/computer-use` 内无任何 audio 相关符号；`Environment`（`target/mod.rs`）两值、`NativeActionKind`（`target/ax_tree.rs`）十值、`ObservationKind` 两值均不含音频，与上节一致。

不在本地继续推进的原因：

- 触发条件未满足：用户尚未选择音频场景并显式开启；2026-10-10 用户限定只推进设计与可模拟拒绝边界。在此之前新增采集代码、依赖或测试内拒绝模拟都会成为无生产入口的假实现（B22 已删除同类模拟）。
- 真实条件缺失：采集权限授予 / 撤销、应用级范围能否隔离、在途流的停止与释放都需要真实桌面 OS 与系统授权手势。2026-10-13 的 Linux 盒（Debian 13 x86_64）没有 `/dev/snd` 设备与 PulseAudio / PipeWire，也不是 macOS，无法提供这些证据。
- Provider 音频往返需单独裁决目标模型与编码通路，当前没有已裁决的音频模型。

解除阻塞的顺序：用户显式开启并确定用途（用户录音或模型输入）→ 按下方剩余工作实施 → 真实环境验收。

## 剩余工作

1. 用户选择音频场景并显式开启后，实现支持范围内的采集与停止 / 释放链路。
2. 真实环境验收应用级音频是否可隔离（不成立则保持 Unsupported）、OS 音频权限授予与撤销、真实流开始后的停止与资源释放。
3. 单独裁决后验收 Provider 音频往返；保存文件不算模型收到音频。
