## 审查方法与证据边界

主代理负责跨包分析、源码复核与文档编写；两名 Sol 分别审查核心与供应商/凭证，两名 Luna 分别审查执行安全与 GUI/协议。主代理另查 workflow、orchestration、control-plane、transport、CLI、宿主入口、testkit 和文档一致性。

读取了各包 Spec、Cargo 声明与相关源码，追踪 Agent loop、事件存储/重放、凭证、工具执行、GUI 连接、任务与用量链路。静态检查的内部普通/build/target 依赖（含 optional）无环；这不是 Cargo 各 feature 组合构建通过的结论。仓库没有 CodeGraph 索引，使用 `rg` 和定点阅读。

“全量”指所有包和主要边界都纳入审查，不代表逐行读完全部源码或穷尽运行行为。发现分为当前装配路径上的问题、库 API 特定调用条件下的问题、需要测量或产品决定的优化候选。每条源码位置均对应上述基线。未运行缺陷复现、Rust 测试、构建、真实 Provider、真窗口或跨平台验收；旧文档中的通过记录只作为历史证据。
