## 1. 多模态与搜索

### MM-1 · 图片端到端验收

剩余工作是按约定模型完成真实识图往返，以及 Desktop 选择→预览→发送→渲染和失败反馈的真窗口验收，同批闭合 RV-01/RV-03。通道限制、Kimi URL gate、CLI 图片参数和 xAI Chat wire 已有实现，不再作为开发任务。

只有验收暴露实际缺口时才修改 providers/cli/desktop 并更新对应 Spec。不扩展图片生成、Files API 或厂商专属增强参数。仓库 [providers Spec](../spec/crates/providers.md) 的 CAP-PROBE 已记录 2026-09-23 通道图片/搜索实测；它不能代替完整产品路径验收，也不是本轮复测。

### MM-2 · 视频契约与产品路径

canonical ContentPart 尚无 Video。先形成视频输入、能力声明、拒绝语义和 wire 草案，按冻结契约要求确认后 golden 先行。逐通道可用 endpoint/格式在实施时重新核对官方文档与可用账号；旧调研不作为永久能力保证。

优先 URL 引用，base64 仅映射官方支持格式；不做本地抽帧/转码或音频，不为不支持通道模拟视频。按 domain/protocol → providers/app → desktop 切片实现，同批更新各包 Spec。验收依次为契约、能力拒绝、wire、具备环境的真实往返和窗口附件路径，缺环境明确待验。

### MM-3 · 剩余搜索接线与来源展示

当前 xAI/ChatGPT Responses 路径和 opencode-go 的 Responses 搜索开关已有源码；OpenCode “未证实因此不声明”的旧待办已失效。剩余任务：

1. 核对 Kimi/Qwen 实际订阅 endpoint 是否支持 Responses web_search；可复用时复用现有组装和 citation 归一，不因同厂商其他套餐支持就放开 capability。
2. GLM Coding 的搜索优先验证既有 MCP 配置路径；通用 API 与订阅计划分开，不另造 engine 厂商分支。
3. 将 [citation 投影](../../crates/protocol/src/projection/mod.rs):269 当前文本输出接到可用的 Desktop 来源展示。优先复用现有事件；若需要改变投影/wire，先明确兼容方案。
4. 正向核查答案、来源链接、未声明能力的拒绝与重放一致；不把 HTTP 成功或普通文本答案当作搜索成功。

写入集按 providers、app、protocol/desktop 实际缺口划分并更新 Spec。DeepSeek、xAI Chat 和未核实 endpoint 继续按现有 capability 拒绝；实施时基于新证据再变更。Agent 侧 webfetch/websearch（B1）、search_provider/search_model 的路由和 Global 配置语义不随此任务扩大。

真实功能验证沿用 [验证规格](../spec/verification.md)：当次 `opencode-go / glm-5.3-flash`，不改持久默认。该模型/账号不支持某专项时记待验；若需要别的模型做能力矩阵，另行明确授权范围，不偷偷替换。
