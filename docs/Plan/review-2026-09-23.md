# 全项目 Review 发现

> 基线 `f14edb23`；方法与覆盖见 [入口](README.md)，逐包定位及 O-01～O-08 优化候选见 [包分析](package-boundaries.md)，实施切片见 [执行计划](remediation.md)。本页全部为静态源码发现，未运行复现，也未修复。

共登记 24 项：8 项 P1、16 项 P2。P1 优先处理安全边界、用户取消与持久状态正确性；P2 处理特定输入、故障恢复和资源生命周期。R-17 是库 API 的并发调用缺陷，当前 CLI 调用方式规避了该条件；其余均有当前产品装配路径。优先级不表示缺陷已在真实环境发生。

## P1：优先修复

### R-01 · 临时文件可跟随符号链接写出工作区

证据：[tools/common.rs](../../crates/tools/src/common.rs):169–199。`atomic_write` 使用 PID + 计数器生成同目录临时名，再 `File::create`；write_file、edit_file、apply_patch 共用它。最终目标经过 policy 校验，临时路径没有独占创建保护。

当目标目录中被预置或竞速创建同名 symlink 时，打开临时文件会截断/写入链接目标，可影响工作区外文件。最小修复是在同目录独占创建临时文件、拒绝跟随已存在链接，只清理本次确实创建的文件；不可只靠随机文件名。验收用外部哨兵文件证明预置链接不能使其改变，并保留正常覆盖与权限语义。

### R-02 · Provider 流错误原文可进入持久化事件

证据：[responses.rs](../../crates/providers/src/responses.rs):938–954、[anthropic/stream.rs](../../crates/providers/src/channels/anthropic/stream.rs):337–354 将上游 message 直接构成 ProviderError；[session_turn.rs](../../crates/engine/src/session_turn.rs):164–170 转为 RunFailed；[event_store.rs](../../crates/storage/src/session/event_store.rs):582–603 按 JSON 键脱敏，不能保证清除普通 message 值里的 Secret。

触发条件是上游错误回显敏感文本；确认的是数据通路，未观察到真实供应商泄漏。最小修复在流错误入口生成有界安全文案，只保留白名单诊断字段；不要通过全局改写聊天正文解决。用含假 Secret 的 SSE 错误验证错误对象、持久事件和投影均不保留原文，正常错误类别仍可辨认。

### R-03 · tasks.json 替换存在丢失窗口和并发覆盖

证据：[tasks_host.rs](../../crates/app/src/tasks_host.rs):78–93 使用固定 `json.tmp`，先删除原文件再 rename；[services/tasks.rs](../../crates/app/src/services/tasks.rs):139–144 取快照后在锁外保存。缺失文件启动时按空 TaskManager 处理（tasks_host.rs:61–68）。

删除后 rename 失败/崩溃会丢失旧快照；多个并发 run 保存会争用同一个临时文件，旧快照也可能后写覆盖新快照。最小修复是串行化取快照到提交、独占临时文件及平台适配的原子替换，失败保留上一份可读数据。验收覆盖替换失败和并发完成后重载，无需新建通用存储框架。

### R-04 · GUI Host 双启动可能抢占活跃 socket

证据：[cli/gui.rs](../../crates/cli/src/gui.rs):48–87、130–149 先探测再绑定，任意探测错误都当作无人监听；[local_unix.rs](../../crates/transport/src/local_unix.rs):15–28 无条件删除已存在 socket，close:139–153 又仅按路径删除。

两个同实例进程都探测到空闲后，后绑定者可 unlink 前者刚创建的活跃端点；PID/token 初始化也处于竞态中，旧 listener 退出还可能删掉新端点。最小修复是覆盖整个 Host 生命周期的原子实例所有权，stale 清理校验所有者，绑定成功后发布 PID。验收同时启动两 Host，只允许一个成功，失败者及旧 listener 清理不得破坏赢家连接。

### R-05 · Task 取消与真实 Run 的令牌、终态脱节

证据：[services/tasks.rs](../../crates/app/src/services/tasks.rs):50–81 忽略 session_id 并单独登记 Task；[task/state.rs](../../crates/workflow/src/task/state.rs):69 创建独立 token；[services/run.rs](../../crates/app/src/services/run.rs):268–308 把另一 token 交给 engine，并仅按 Result 的成功/错误映射 Completed/Failed。GUI 使用 [bus.rs](../../crates/app/src/gui_host/bus.rs):306 的运行注册表。

Task cancel 可以把任务记为 Canceled，而执行中的 Run 继续；GUI 取消则可能使任务记为 Failed。CLI `tasks` 另起进程读取快照，单纯在一个 TaskManager 中共享 token 仍不能完成跨进程取消。最小方案是在 app 绑定 task/session/run，取消路由到实际拥有执行体的 Host，任务终态从真实 Run 终态映射；无活跃所有者时如实拒绝或收为中断。若需要新增 GUI 命令，按冻结契约流程单独审定。验收两个入口都停止同一个阻塞 run，终态一致且仅写一次。

### R-06 · 同会话 RunStart 缺少完整的接受隔离

证据：[run_start.rs](../../crates/app/src/gui_host/handlers/run_start.rs):168 先读取历史，299–349 的装配持 core 写锁，408–443 按 run_id 登记后 spawn，执行期间持 core 读锁；[event_store.rs](../../crates/storage/src/session/event_store.rs):316 起要求全 session sequence 连续。

第二个请求可先读取未完成首轮的历史，再等装配写锁；等首轮结束后也不会重新读取历史。两个请求在首轮执行读锁建立前突发进入并完成装配时，还可能都获 Accepted，执行阶段读锁允许并发、各自起算 sequence，交错事件可相撞。写锁只保护装配，并未保护“读历史→登记→执行”这一完整过程；不能把所有重入都描述为立即并发。

最小修复是读取历史前取得 session 活动槽，所有早退和终态释放；优先显式拒绝同 session 第二个 run，避免加队列。验收首轮运行中和两请求突发两种时序，第二轮均确定性拒绝；首轮终止后重试带正确历史与 sequence。跨 session 的既有行为不在这次修复中扩大。

### R-07 · 压缩保留集合与重放水位不一致

证据：[retention.rs](../../crates/storage/src/session/compaction/retention.rs):183 保留 System；[loop_ctx.rs](../../crates/app/src/loop_ctx.rs):291–307 将未保留消息的最大 sequence 作为折叠水位；[projection.rs](../../crates/storage/src/session/projection.rs):600–628 只读水位之后消息；[engine compaction.rs](../../crates/engine/src/tool_loop/compaction.rs):398 附近又按尾部重建当前请求。

早期 System 位于后来被折叠的普通消息之前时，保留策略与实际恢复结果冲突，重启后仍会被水位过滤；当前请求和重放也可能不同。最小方案是让当前请求与持久投影消费同一保留决定。单一水位只能表达连续后缀，不能继续声称支持任意保留集合；若需改持久契约，先形成草案与 golden。验收包含早期 System、折叠旧轮和保留尾轮，压缩前后及重启后的可见消息符合相同规则。

### R-24 · 只读 CLI 装配会清扫其他活跃 Host 的 Run

证据：[cli/lib.rs](../../crates/cli/src/lib.rs):424–444 中 sessions/models/usage/tasks 等命令走 AppCore::load_for_catalog；[app_core.rs](../../crates/app/src/app_core.rs):481 打开相同 instance 数据库，1029 无条件执行 seal_interrupted_runs；[services/session.rs](../../crates/app/src/services/session.rs):233–306 把库中所有 Running 当崩溃孤儿。GUI 的 ensure_single_instance 位于装配之后，不能保护这一步。

一个 Host 正在运行时，另起同 instance 的 sessions list 等查询即可进入清扫，将活跃 Run/工具写成失败，干扰原进程之后的 sequence 与终态写入。最小修复是分离普通打开数据库与恢复写入，只有取得实例执行所有权并确认前任退出的 Host 才能清扫；所有权应早于打开/恢复。验收活跃 Host 执行阻塞 run 时运行旁路查询，事件库零额外失败事件；原所有者真正退出后，新所有者仍可幂等恢复。

## P2：可靠性与资源边界

### R-08 · 畸形流片段被忽略后仍可成功

[Chat stream.rs](../../crates/providers/src/stream.rs):15–18、[Anthropic stream.rs](../../crates/providers/src/channels/anthropic/stream.rs):46–49 的 JSON 解析失败返回空事件；后续 `[DONE]`（[provider.rs](../../crates/providers/src/provider.rs):184）或 message_stop 仍可终止成功。正文或工具参数可能缺失。将畸形载荷转为 MalformedResponse，保留合法 ping/未知扩展事件的兼容语义；验收“畸形片段 + 正常终止”，不能仅测缺少终止标记。

### R-09 · 等待工具并发槽时取消无效

[scheduler.rs](../../crates/tools/src/scheduler.rs):359–378 直接等待 semaphore，拿到 permit 后才检查取消。槽位长期占满时，取消的请求仍排队；工具 timeout 也尚未开始。获取 permit 与取消 token 应 select；验收在不释放 permit 的情况下取消排队请求，及时返回且 executor 不被调用。

### R-10 · 文件写超时后阻塞任务仍继续执行

[scheduler.rs](../../crates/tools/src/scheduler.rs):338–355 的 timeout 丢弃 execute future；[write_file.rs](../../crates/tools/src/write_file.rs):64、[edit_file.rs](../../crates/tools/src/edit_file.rs):81、[apply_patch.rs](../../crates/tools/src/apply_patch.rs):113–124 使用 spawn_blocking 且忽略 cancel。已运行的闭包不会随等待 future 丢弃而停止，apply_patch:178 起仍可能继续多项写入。

超时/取消终态与后续磁盘变更不一致。将取消传入闭包，在提交与每个操作边界检查；宿主必须等待已开始的不可中断提交完成或跟踪其最终结果，不能谎报已停止。验收受控多操作补丁取消后不再开始后续操作，返回状态与最终文件一致；不要求通用文件事务框架。

### R-11 · GUI 连接句柄累积且 shutdown 跳过 Core

[cli/gui.rs](../../crates/cli/src/gui.rs):95–103 仅移除与新连接 ID 相同的旧句柄，唯一 ID 下不会回收已断连句柄；状态探测也会建立短连接。124 行 `Arc::try_unwrap(core)` 时 server/listener 仍经 [gui_server/mod.rs](../../crates/app/src/gui_server/mod.rs):100–158 的 Inner.host 持有 core，正常路径不能获得独占所有权。

长驻 Host 持续积累句柄，退出时显式 Core shutdown 被跳过。复用 [SessionHandle](../../crates/app/src/gui_server/session.rs):34–91 已有完成通知管理活跃连接；退出先停止接受、关闭并等待会话、释放 Host 持有者，再完成 Core shutdown。验收重复短连接后集合回落，并证明关闭路径确实等待 Core 结束；不只检查进程能退出。

### R-12 · 迟到 Snapshot 可被下个请求接收

[client/lib.rs](../../crates/client/src/lib.rs):966–969 的 Snapshot 匹配没有 request_id。串行锁挡住同时请求，但旧请求超时后，迟到回复可满足新请求，返回旧状态。最小缓解是 Snapshot 超时即废弃该连接并恢复；下次 wire 演进再加 request_id。验收首个超时、其回复延迟到第二次请求期间，旧帧不得成为第二个结果。

### R-13 · 新用量与旧 quota 窗口出现在同一 overview

[services/usage.rs](../../crates/app/src/services/usage.rs):58 成功写账本后未失效 quota；92–94 先读新总量再读窗口；[quota/service.rs](../../crates/control-plane/src/quota/service.rs):721/998 默认 30 秒缓存命中直返。当前本地 ledger adapter 可显示最多约 30 秒不一致。入账后失效相应本地窗口缓存，保留远端额度自身的缓存口径；验收先读、入账、立即再读，同作用域窗口同步更新。

### R-14 · search_text 单文件读取内存无界

[search_text.rs](../../crates/tools/src/search_text.rs):180–185 在输出预算前 read_to_string 整文件。巨型文本文件会使内存随输入大小增长，输出截断不能约束它。优先有界读取/流式扫描，或明确单文件上限并报告跳过原因；验收超限文件不被完整装入内存、取消及时且结果不冒充完整搜索。

### R-15 · 服务定义未正确编码可执行文件路径

[cli/service.rs](../../crates/cli/src/service.rs):61–64 把 exe 直接写入 Linux ExecStart；70–93 在 macOS XML string 中直接插值。合法路径含空格时 systemd 参数可能拆错，含 `&`/`<` 时 plist 无效。按目标格式编码字符串，验收解析后还原完整 executable/argv；不通过真实安装系统服务验证文本生成。

### R-16 · agents demo 留下永久 Running 任务

[orchestration_host.rs](../../crates/app/src/orchestration_host.rs):86–89 丢弃 tasks_start_agent 返回 ID；98–121 只结束 supervisor worker，不结束 workflow task。每次 demo 都可往 tasks.json 留无执行体的任务。最小方案是演示不登记生产 Task，或持有 ID 并在全部终态配对结束；验收执行/取消 demo 后没有新增悬空 Agent 任务。

### R-17 · listener.close 不能唤醒挂起的 accept（库 API）

[local_unix.rs](../../crates/transport/src/local_unix.rs):118–122 持 mutex 等 accept，close:141 等同一个 mutex；无客户端时并发 close 无法完成。Windows [local_windows.rs](../../crates/transport/src/local_windows.rs):165–197 的 closed 标记同样不唤醒已挂起的 connect。当前 CLI select 会先丢弃 accept future，再调用 close，因此不把它误报为现有 Ctrl-C 必挂。

用关闭通知驱动等待并保证重复 close 幂等；Unix 不删除其他所有者端点（与 R-04 配合）。定向验收并发 pending accept/close 在有界时间结束；Windows 结论需在对应平台实际验收。

### R-18 · 摘要请求取消后压缩仍提交

[engine compaction.rs](../../crates/engine/src/tool_loop/compaction.rs):281 对包括取消在内的错误降级结构摘要，356 起继续宿主压缩和事件写入；[loop_ctx.rs](../../crates/app/src/loop_ctx.rs):195 的 `_cancel` 未使用。取消期间仍可写 recovery branch、摘要和 CompactionCompleted，手动入口可返回成功。区别取消与可降级错误，在摘要后和持久提交前检查取消；验收取消摘要后不产生完成事件，手动调用返回取消。

### R-19 · 已 Accepted 的前置失败缺少可重放终态

[run_start.rs](../../crates/app/src/gui_host/handlers/run_start.rs):408–465 先异步接受；[services/run.rs](../../crates/app/src/services/run.rs):117/223 的 Plan/能力门可在 RunStarted 前拒绝。兜底只追加 RunFailed（run_start.rs:35），[projection.rs](../../crates/storage/src/session/projection.rs):552 要求 run 行已存在，失败后回退实时合成事件（run_start.rs:68）。

客户端见到失败，重连/重启却找不到该 run 的持久终态。可预判闸门前移到 Accepted 之前；必须异步失败的路径应先建立合法持久生命周期。验收 Plan 未批准时响应与重开 store 后状态一致，不靠额外广播掩盖写库失败。

### R-20 · 归档会话被崩溃清扫漏掉

[services/session.rs](../../crates/app/src/services/session.rs):233 用 list_sessions 清扫；[catalog.rs](../../crates/storage/src/session/catalog.rs):143 排除 archived；session.rs:132 的归档不要求 run 已结束。运行中归档再退出，重启后仍可留下 Running。维护查询应覆盖全部会话，用户列表继续隐藏归档项；验收归档悬空 run 重开后补单个失败终态，重复打开幂等。

### R-21 · 崩溃恢复未归集已持久化 usage

[services/session.rs](../../crates/app/src/services/session.rs):306 补 RunFailed 时 usage=None；[services/usage.rs](../../crates/app/src/services/usage.rs):119/166 从终态读用量；[services/run.rs](../../crates/app/src/services/run.rs):290 后才记录独立账本。若 UsageUpdated 已落盘但宿主在终态前退出，已知部分用量不进终态和账本。

恢复时按 request 归集最新用量快照，再写补偿终态并幂等入账；不把同一 request 的累计快照反复相加，也不推测上游未回报的用量。验收持久化 Started/RequestStarted/UsageUpdated 后重开，两处读数有已知用量，第二次重开不重复计账。

### R-22 · 终态后账本写失败没有补账路径

[services/run.rs](../../crates/app/src/services/run.rs):294–300 账本失败只 warn，返回原 Run 结果；启动维护未对已完成终态对账。session 已完成而 usage ledger 写失败时会长期漏记。复用持久终态和稳定幂等标识进行可重试补账，暴露待对账状态；不要为账本失败把已成功的模型运行改成失败。验收一次注入入账失败后恢复，仅补一次且 Run 终态不变。

### R-23 · 重启后 Task 快照仍声称旧任务运行中

[tasks_host.rs](../../crates/app/src/tasks_host.rs):61–75 只 replay，[task/manager.rs](../../crates/workflow/src/task/manager.rs):221 起只恢复状态日志，token 被重新创建，没有执行体。Run 中途退出后 tasks list/status 可永久显示 Running。真实 Host 启动时按所有权与可恢复性将孤儿 Agent 任务收为失败/中断并持久化；不能在另起 CLI 读取快照时误终止仍由其他活跃 Host 拥有的任务。验收所有者退出后重载不再 Running，活跃所有者存在时不被误扫，重复恢复幂等。

## 未认定为当前故障的事项

未发现应按“通用路径解析失效”处理的证据，R-01 是临时文件打开的独立缺口。run_command 已清空环境并按白名单补回，不能据 Host 有凭证就认定子进程泄漏。computer-use 的专用 loopback/RFB 部署边界符合当前 Spec，不自行扩大为远程认证改造。

engine 的摘要内部请求不计入 run_usage 是现行口径，缺少自动 retry 也不能仅凭错误含 retryable 就认定缺陷。未装配 DAG/merge、durable lease、条件 API 和性能测量统一放在包分析，不与以上产品路径问题混排。历史 OAuth 刷新、request_id 命名空间和旧 GUI 静默断连记录已关闭，不重复挂牌。
