# Pawork GUI 用户视角验收（2026-09-09）

## 1. 结论

**核心对话已经可用，但本次整体验收不通过。** 主要障碍是长草稿编辑、回复内容的使用、项目归属引导和错误恢复；继续只调色板或圆角，不能解决这些日常操作问题。已整理为 [活动 ROADMAP](../ROADMAP.md) 的 4 项 P1、5 项 P2，全部待实施。

观感上，深灰色工作台、居中的阅读列和输入卡片、低强调工具折叠、统一设置导航已经建立稳定风格。普通中文正文、粗体、行内代码和代码块能阅读；设置页比工作台更整齐。但辅助信息偏碎、部分页面空白过大、图标和字段的作用不够直观；表格、错误、空态和账号信息仍明显带有开发工具内部状态的表达方式。这里是基于当前截图的设计判断，没有虚构竞品对照、用户满意度分数或可访问性认证。

## 4. 问题与改进意见

### F01 — P1：长段落输入无法在发送前完整审阅

截图 04 中整段中文横向排成一行，右侧超出输入可见区；截图 29 的显式换行可以正常显示，说明问题是软换行而非所有多行输入失效。源码 `apps/desktop/src/ui/text_input.rs` 的布局按已有换行计数，`prepaint` 对每个 `line_byte_ranges` 调用 `shape_line`，与现象一致。

用户需要在阅读宽度内检查、修改提示词。优先实现按宽度换行，并同步光标 / 选择 / 输入法坐标；不能只把输入框加高。对应 UX-01。

### F02 — P1：回复能看见，仍不方便取用

截图 06 / 18 的表格显示原始 `|` 和 `---`；代码虽然有背景区，但无语言标题和复制按钮。截图 19 中点击助手回复的省略号，只看到禁用的“分叉”，没有复制或原因说明。源码 `ui/markdown.rs` 的块类型没有表格，链接转成可读文本而无打开动作；`entry_actions_element` 只创建 Fork。

补常用表格呈现、回复 / 代码复制及链接动作；把分叉放到用户能理解的回合边界。不默认引入全套编辑器或完整 IDE。对应 UX-02。

### F03 — P1：项目筛选与任务归属形成认知陷阱

截图 20 的项目入口藏在左上范围菜单里。选择 workspace 后，截图 21 的侧栏为空，中央却仍显示原来的无项目对话，底部继续要求“选择项目”。随后在该作用域新建任务才获得项目。这是现有筛选语义，不是后端绑定失败，但文案无法帮助用户理解。

保留已有任务归属不变，明确筛选作用，并在无项目提示旁提供“在项目中新建任务”的可执行入口。对应 UX-03。

### F04 — P1：失败原因离操作太远，恢复步骤不清楚

截图 25 / 26：Start 可点击；只读拒绝后，终端仍显示“终端输出将显示在这里”，只有极小标题和 Composer 下方出现被截断的英文 `ProtocolError`、`Internal`、`ADR-041` 等信息。权限拒绝是正确行为，问题在于没有预先解释、失败没有就地落点、也没有用户可行的下一步。

截图 40 / 41：无效端点导致缺 token 的真实失败，中央仍显示“开始一个任务”和禁用按钮，模型仍显示“加载中”；设置提示“显示最后已知状态”，但这是从未连接过的窗口。重连仍失败，缺少区分暂时断开和启动配置错误的解释。应就地解释并保留可展开诊断详情，不能以自动放宽权限来改善流程。对应 UX-04。

### F05 — P2：模型多了以后靠反复滚动找

截图 03 的当前值是 `glm-5.3-flash`，打开菜单后显示的是 DeepSeek 与 Go 列表开头；当前项不在可见区域。截图 09 的模型管理共 20 项，弹层仅展示约 4～5 行，名称与 ID 重复占高，无搜索。

当前 DeepSeek 的两条旧名称来自未连接供应商的现有目录 / fallback 状态；本次没有真实 DeepSeek 凭证验证，**不能据此断言 UI-6a 的远端替换逻辑回退**。用户真正面对的问题是无法区分未认证 / fallback 与当前可运行模型。定位当前项、搜索和来源 / 连接状态说明即可改善。对应 UX-05。

### F06 — P2：账号管理的信息优先级与时间表达不便理解

截图 07 中四个角色默认值占据首屏大部，唯一连接的 Go 在三个未连接供应商之后。识图 / 搜索仍是可选择控件，旁边却提示路由未接线。截图 08 的账号区把名称、认证、选择、额度、自动切换和新增表单堆在同一大背景面上，动作层次较弱；三窗可读，但“6995 分钟后重置”需要用户自己换算。

应优先呈现已连接供应商和当前账号，按账号分组显示三窗、易读重置时间和过期状态；“未生效”与可用配置区别更明显。底栏“配额不可用”与账号页真实额度可能指向不同范围，应解释范围，不能简单复制或合并数字。对应 UX-06。

### F07 — P2：工具与完成状态丢失有用信息

截图 23 展开后仅显示 `list_directory` 和“已完成”，无法直接知道目录、返回 0 项还是没有返回。SQLite 中真实结果包含 `path='.'`、`total=0`、`entries=[]`，本地目录也确实为空，说明可以从权威结果解释空态。报告不把模型的空目录解释当作独立工具证据。

截图 24 的 Changes Summary 与底部状态大量显示 unknown / 不可用；无数据不应造假，但两个完成 Run 都有 `usage_updated` 事件，而工作台仍显示“任务 — tokens”。应先定位该事件到显示的缺口。取消后的大卡、说明和页脚反复陈述同一终态（截图 30），可以收紧。对应 UX-07。

### F08 — P2：归档可执行，但用户找不回来

截图 31：归档取消测试任务后，任务立即消失且工作台回空态，没有撤销提示，也未见“已归档”范围。数据库确认记录仍在、`archived=1`。这不是数据删除，而是 GUI 的恢复发现性缺口。

提供短反馈和可操作恢复路径，优先复用现有能力；不能靠永久删除确认替代归档恢复。对应 UX-08。

### F09 — P2：视觉基本统一，产品语言与细节仍碎片化

已确认的优点：深灰色层级基本一致；蓝色主要动作可识别；正文与输入卡片对齐；工具 / 思考默认折叠；设置分区、导航选中态和三档字号清晰。没有必要再推倒重做整个壳。

剩余问题：中文页混入 You、New session、Files / Summary、Start、tool completed；Network / Advanced 文案包含 Host、workspace、配置路径和实现限制，普通用户要自己翻译意图。MCP 空态先解释不存在的 Test / Remove，未给配置的下一步。账号文本偏小，Terminal 顶栏拥挤，稀疏设置页空白多；大字号小窗口下文字更清晰，但侧栏和模型槽保留宽度不足，读正文需要更多滚动。

截图和 Tab 操作只能确认局部可访问性：截图 33 有清楚焦点，Esc 可以回到模型 / 消息菜单触发器；未测完整旁白读序、色彩对比比值、所有焦点环路或 IME。部分 AX 操作返回 `elementHasNoFrame`，换成可见坐标能操作，尚不能区分工具映射问题和应用 AX 问题，应作为待复验项，不能直接升级为已确认缺陷。对应 UX-09。
